DSASlow writes · fast reads

A write head. A read head.

Remove duplicates (or zeroes, or a value) in-place on a sorted array: one pointer writes the next kept slot, the other reads. Fast scans; slow only advances when you keep. Order of kept items stays. Return the new length; the tail is garbage.

1

Sorted dups[0,0,1,1,1,2,2]. slow=0. fast=1..: when a[fast]!=a[slow], slow++, then a[slow]=a[fast]. Result [0,1,2,…] len=3.

What

O(n) time, O(1) extra. Sorted is what makes “equal to previous kept” the dup test. Unsorted dups need a set (extra space) or sort first. Return the new length; do not shrink the allocation.

Why

LeetCode 26 / 27 / 283. The write/read split shows up in any compact-the-array problem. Say which pointer is the next open slot, which one scans.

Trap

Deleting from a list while indexing forward (you skip the next). Using an extra array after in-place was required. For “at most twice” (LC 80): compare with a[slow-2], not a[slow-1].
