Networkcwnd · congestion

Slow start is TCP feeling the pipe.

A new TCP connection does not dump your 2MB JS at line rate. Congestion window (cwnd) starts small and doubles each RTT until loss or a threshold — short flows live in slow start, so reuse matters (plate 277).

Many round trips to fill the path. Loss shrinks the window and you probe again.

Warm connection

cwnd open

same fd, already open cwnd already grown bytes flow no extra handshake no extra slow start

BBR vs cubic are the controllers. You do not set cwnd in app code — you avoid extra handshakes.

What

TCP probes the path. Loss shrinks the window. RTT is in the inner loop.

Why

Latency budgets, CDNs near the user (plate 36), connection reuse, HTTP/2 (plate 274).

Trap

Opening a connection per image. Measuring bandwidth with a 20KB payload still in slow start. Saying “TCP is slow” when you meant the handshake.
