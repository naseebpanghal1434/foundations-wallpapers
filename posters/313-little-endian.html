Archx86 · network big-endian

Little-endian stores the low byte first.

uint32 0x01020304 in memory on x86: 04 03 02 01. Network protocols (TCP/IP) use big-endian (htonl/ntohl). File formats specify one; mixing without conversion is a portability bug, not a style.

x86 / ARM (usual)

Little

0x01020304 addr+0 04 addr+1 03 addr+2 02 addr+3 01

Low byte at the low address. One-byte values are immune.

vs

TCP/IP · many files

Big

0x01020304 addr+0 01 addr+1 02 addr+2 03 addr+3 04

Java DataOutputStream is BE. Protobuf has its own encoding. UTF-8 is byte-oriented; UTF-16 needs a BOM or a spec.

What

Byte order of multi-byte integers. ASCII/UTF-8 has no endian.

Why

Packet parsing, binary files, mmap’d structs between machines.

Trap

Casting a packet buffer to uint32_t* on LE and comparing to a BE spec constant. Assuming ARM is BE — phones and servers are almost always LE.
