ToolsPIC · PLT · GOT

A .so is relocated at load. A .a is copied in.

A static .a is an archive of .o files: ld copies needed objects into your binary (plate 325). A shared .so/.dll is mapped at load; PIC + PLT/GOT resolve symbols, and one text segment is shared among processes. ldd prints DT_NEEDED; RPATH/RUNPATH vs LD_LIBRARY_PATH pick the file.

Link time · bytes inside

.a

ar rcs libfoo.a a.o b.o ld copies used .o in huge binary no runtime dep on foo patch foo → relink

The archive is a pile of objects, not a mapped library. Unused .o stay out.

Load time · one mapping

.so

libc.so.6 DT_NEEDED ld-linux maps ET_DYN PIC text shared PLT lazy / GOT patched ldd ./app RUNPATH vs LD_LIBRARY_PATH

Windows DLL search order is a CVE magnet. Dynamic needs ABI stability (plate 326).

What

When the bytes join your address space. Static: copied by ld. Dynamic: relocated by the loader.

Why

Disk, RSS, updates — patch libc without relinking the world. One .so text segment, many processes.

Trap

LD_LIBRARY_PATH in prod as architecture. Mixing two libstdc++.so. Undeclared indirect deps that only work because something else loaded them.
