Frontendvalue + onChange

Controlled means React owns the value.

A controlled input is value={state} plus onChange — React owns the value; the DOM is a mirror. Uncontrolled uses defaultValue and a ref; the DOM owns it until you read.

React is truth

Controlled

<input value={name} onChange={e => setName(e.target.value)} /> // keystroke → render

One-way data. Checkboxes use checked, not value.

vs

DOM is truth

Uncontrolled

<input defaultValue="ada" ref={r} /> // submit: r.current.value

Native until you ask. File inputs are uncontrolled by spec.

What

Controlled = React owns the value. Uncontrolled = the DOM owns it until you read. Form libraries pick a side.

Why

The “input doesn’t type” bug is value with no setter. Async setState on each letter also jumps the cursor.

Trap

value={x} and no onChange freezes the field. Switching uncontrolled → controlled mid-life warns. Do not set both defaultValue and value.
