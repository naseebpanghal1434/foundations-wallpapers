SystemThundering herd

A miss is a crowd.

A hot key expires. Two thousand concurrent requests miss together and all hit the database for the same row. That is a cache stampede (dogpile, thundering herd). The cache was the rumor (plate 08). The miss is a coordinated attack on the source of truth.

Singleflight coalesces one box. A Redis lock coalesces the fleet. SWR keeps the rumor alive on purpose.

What

Stampede = concurrent miss on one key (or many keys with the same TTL). Fixes: request coalescing, mutex around fill, stale-while-revalidate, probabilistic early refresh, TTL jitter. Hot keys can skip expiry and refresh on a timer.

Why

The cache exists to protect the DB. A synchronized miss inverts that. Interviews pair this with plate 08 and with jitter (plate 19): don’t let everyone wake up on the same clock.

Trap

Aligned TTLs — warmup or deploy sets 10k keys to EX 60 in the same second; they all die together. In-process singleflight with 20 app boxes (20 DB hits). Lock without a TTL (refresher dies, lock stuck). Flushing Redis “to fix stale.”
