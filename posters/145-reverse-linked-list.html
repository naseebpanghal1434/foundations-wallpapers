DSAprev · cur · nxt

Three pointers reverse a list.

Reverse a singly linked list in O(n)/O(1): prev=null, cur=head. Save nxt=cur.next first; then cur.next=prev; prev=cur; cur=nxt. Return prev. Recursion (reverse the tail, then head.next.next=head) is O(n) stack — fine for small n, not for 10⁵.

Save nxt, then flip

Whole list

prev, cur = null, head while cur: nxt = cur.next # first cur.next = prev prev = cur cur = nxt return prev 1→2→3→null null←1 2→3 null←1←2 3 null←1←2←3

Return prev, not the old head (now the tail). O(n) time, O(1) extra.

Range [l, r] · 1-indexed

Sublist

dummy.next = head walk to node l-1 flip r-l+1 links reconnect both ends k-group (LC 25): this in chunks of k leftover tail stays

Dummy so the predecessor of l always exists. Doubly-linked reverse is swap prev/next everywhere.

What

Iterative three pointers. Dummy for a sublist reverse so the predecessor is easy. Palindrome list: reverse the second half (plate 149). Always draw one node flipping.

Why

LeetCode 206 / 92 / 25. The first linked-list screen. If you can reverse, you can splice, k-group, and palindrome. Recursion is the same flip after the tail returns — name the stack cost.

Trap

Losing nxt — cur = cur.next after you already set cur.next = prev. Returning head (now the tail). Recursing n=10⁵. Off-by-one when reversing a 1-indexed range [l,r].
