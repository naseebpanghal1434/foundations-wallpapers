FrontendReact hooks

useEffect is a sync, not mount.

useEffect means: keep this side effect in sync with these values. The dependency array is the list of values. Empty array is not “componentDidMount” — Strict Mode will run it twice in dev to catch missing cleanup.

Wrong mental model

Lifecycle

useEffect(() => { fetch(`/users/${id}`) }, []) // stale id forever useEffect(() => { fetch(`/users/${id}`) }) // fetch every render

[] ignored id. No array = run after every paint. Both hurt.

vs

Sync with the world

Deps + cleanup

useEffect(() => { let live = true fetch(`/users/${id}`).then(...) return () => { live = false } }, [id]) // re-run when id changes

When id changes, cleanup the old fetch, start the new one.

What

After paint, React runs effects whose deps changed. The function you return is cleanup for the previous run. If it talks to the world (network, timers, subscriptions), it belongs in an effect. If it computes UI, it does not.

Why

Data fetching, event listeners, and document.title are sync problems. Putting fetch in the body of the component fires during render. Missing deps is a stale closure (plate 23).

Trap

Lying to the linter (eslint-disable on deps). Object/array deps created inline change every render. For “mount once” data, prefer a loader / TanStack Query / a key on the component, not empty deps plus a shrug.
