DSATwo sorted lists

Dummy head. Pick the smaller.

Merge two sorted linked lists into one sorted list. Dummy sentinel, tail walks. Each step: attach the smaller head, advance that list. Then attach whatever remains. O(m+n), O(1) extra. Do not allocate new nodes unless asked — relink.

1

Dummy so the empty case is freedummy = Node(0); tail = dummy. Never special-case “the result was empty.” Return dummy.next — returning dummy is the bug.

sentinel
2

1→4→5 and 1→2→3→6. Pick minAttach 1 (a), 1 (b), 2, 3, 4, 5, 6. Compare a.val vs b.val, not the nodes. tail.next = smaller; tail = tail.next.

relink
3

Leftover tail hangs on in one writetail.next = a or b. Merge k lists is this in a heap (plate 161) or pairwise. Recursion: return the smaller node, its next = merge(rest) — O(n) stack.

rest
What

Same as merging arrays from the front (you own new links, no clobber — unlike plate 134’s fill-from-the-back). Relink existing nodes. Dummy is one code path for empty and non-empty.

Why

LeetCode 21. Foundation for merge sort on lists (LC 148) and k-way merge. Interviews watch whether you allocate a parallel list of new nodes, and whether you return dummy.

Trap

Forgetting the leftover tail. Using a dummy and returning dummy not dummy.next. Comparing node vs node.val. Creating new nodes when relink was enough.
