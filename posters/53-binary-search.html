DSAThe lo / hi invariant

Binary search needs sorted data.

Halve the range only if the array — or the answer space — is ordered. Keep an invariant: the target, if it exists, is inside [lo, hi]. Mid splits; one side dies. O(log n) comparisons. Unsorted input makes the halves meaningless.

Monotonic · answer in range

Invariant

lo, hi = 0, n-1 while lo <= hi: mid = lo + (hi-lo)//2 if a[mid] == t: return mid if a[mid] < t: lo = mid+1 else: hi = mid-1

Pick <= vs < and stick to it. Mid must move. First-bad-version is the same idea on a predicate.

trap

Unsorted, or 32-bit mid

Miss / overflow

binary_search([4,1,9], 4) # halves are noise; may miss mid = (lo + hi) / 2 # 32-bit int: lo+hi wraps # then mid is wrong forever

lo + (hi-lo)/2 cannot overflow the sum. Infinite loop: hi = mid when mid == hi.

What

The predicate must be monotonic (false… then true…). Same algorithm on a raw array or on “minimum capacity that works” (binary search the answer). O(log n) time, O(1) extra space.

Why

n = 10⁹ brute is dead; ~30 doublings cover it. Screens: search-insert, rotated array, first/last occurrence. State the invariant out loud before you move lo/hi.

Trap

Running it on unsorted data. Off-by-one (lo < hi vs <=, mid+1 vs mid). Overflow on (lo+hi)/2. Loop that does not shrink the range.
