Systemdeadline · jitter · 429

Time out. Then back off.

A socket can block forever. Set a deadline: HTTP 2 s, DB 5 s, connect() 200 ms. Retry only idempotent calls (GET, PUT with If-Match, POST with Idempotency-Key, plate 225). Full jitter: sleep = rand(0, min(cap, base×2^n)) so clients do not retry on the same clock.

100 · 200 · 400
What

Timeout bounds wait. Retry repeats. Exponential backoff + jitter desynchronizes clients. Default is 3 attempts, then fail.

Why

A 200 ms blip should not stall workers or stampede the recovered host (plate 94). Interviews: name jitter and idempotency.

Trap

Retrying POST /charge on timeout — the 200 may have committed; without an idempotency key you capture twice. Retrying 400s. No jitter: every client hits t=1.0 s together.
