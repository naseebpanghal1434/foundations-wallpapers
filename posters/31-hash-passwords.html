Backendbcrypt cost 12 · Argon2id

Hash passwords. Don't encrypt them.

AES is reversible with the key. A password hash must not be. Store a slow KDF of password+salt — bcrypt, Argon2id, scrypt — never plaintext, never AES. Login: hash the attempt, crypto.timingSafeEqual. A stolen users.password column must not yield the passwords.

bcrypt cost

12

2^12 = 4096 Blowfish rounds. +1 cost doubles time. ~200–400 ms/hash on a CPU.

stored string

$2b$12$

cost + 22-char salt + 31-char hash. Salt is unique per row (16 B entropy).

Argon2id (OWASP)

19 MiB

m=19456 KiB, t=2, p=1. Memory-hard: GPUs hate it. Prefer this for new work.

SHA-256 on GPU

~10⁹/s

Too fast. MD5/SHA-1/SHA-256 are checksums, not password hashes. Rainbow tables if unsalted.

What

One-way KDF. bcrypt cost N = 2^N iterations. Login recomputes with the stored salt and compares in constant time. Pepper (optional) is an app-wide secret. Reset issues a new secret; you cannot “look up” the old one.

Why

Dumps happen. Users reuse passwords. If you can email someone their current password, you encrypted (wrong). Default interview filter.

Trap

SHA-256 “because it’s a hash.” Truncating bcrypt (72-byte input cap). Comparing with ==. Cost 4 in tests shipped to prod. Client-side hashing as the only step — the server hashes what it stores.
