FrontendReconciliation

Keys tell React which child.

React compares the new tree to the old one. For lists, key is the identity of a row. A stable id means “this is the same item.” The index means “whoever sits in slot 2” — which breaks when the list reorders.

key=index · shuffle

Wrong identity

[0 Ada input:"hi"] [1 Kai] delete Ada [0 Kai input:"hi"] ← Kai stole Ada’s state

React reused slot 0. The input text followed the index, not the person.

vs

key=user.id

Same person

[id:7 Ada input:"hi"] [id:2 Kai] delete Ada [id:2 Kai input:""] ← Kai kept Kai

React matches by id. State stays on the component instance that owns it.

What

Reconciliation: same type + same key = update. Different key = unmount + mount. Keys must be stable and unique among siblings, not globally.

Why

Inputs, accordions, animations, and useState live on the instance. If identity is wrong, you get ghost text, lost focus, and “React didn’t rerender.”

Trap

key={index} on a list that can sort, filter, or insert. Or key={Math.random()} which remounts every render and resets state. Use the row’s primary key.
