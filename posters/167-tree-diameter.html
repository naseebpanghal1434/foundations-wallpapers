DSALongest path through a node

Height of left plus height of right.

Diameter of a binary tree: longest path between any two nodes, measured in edges. It may not pass through the root. DFS returns height. At each node, candidate = hL+hR, then a global max. Return 1+max(hL, hR) to the parent — never the bend. O(n). One extra global, or a pair return.

Candidate at every node

hL + hR

1 / \ 2 3 / \ 4 5 null → 0 leaf → 1 at 2: 1+1 = 2 (4-2-5) at 1: 2+1 = 3 (4-2-1-3) diameter 3

Return height up. Track the best bend globally. Path-sum-through-a-node is the cousin (plate 171).

vs

Root only · or a stick

Not enough

1-2-3-4 n=4 height n-1 = 3 diameter 3 edges not 2 × height root-only hL+hR misses a fat child

You must visit all nodes. Graph diameter of a tree is two BFS (any node → farthest → farthest) — not this recursion.

What

Combine: best path through me vs best already found in a child. Height down is what the parent needs; the fork is only a candidate. Null returns 0 so a leaf’s hL+hR is 0 (diameter of a single node is 0).

Why

LeetCode 543. The height DP. Interviews: “does it have to go through the root?” No. Say edges, say global, say you return height. N-ary / undirected tree: two BFS, not this.

Trap

Returning the height as the diameter. Only computing at the root. Counting nodes not edges (off-by-one). Returning hL+hR to the parent — that is a bend the parent cannot use.
