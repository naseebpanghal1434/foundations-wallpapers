FrontendCookie · localStorage · session

Cookies travel. Storage stays.

A cookie is sent on matching HTTP requests — that is the point and the cost. localStorage stays in the origin; sessionStorage dies with the tab. If the server must receive it, it is a cookie (or a header you set).

Sent on the request

Cookie

Cookie: sid=… every GET /api ~4KB, auto-sent

httpOnly (plate 232) is the session default. Cost: bytes on every matching request, including images.

Origin, no auto send

localStorage

origin, 5MB+ JS read/write server never sees it

Drafts, prefs, caches. JWT here is XSS-bait (plate 234). Survives tab close.

Dies with the tab

sessionStorage

per tab same origin gone on close

A duplicate tab is a new bag. Not a session cookie. IndexedDB is structured and async.

What

Cookie = request-scoped credentials. Web storage = client cache. IndexedDB is structured and async.

Why

“Where do I put the token?” If the API needs it, prefer a cookie. If it is a draft document, storage.

Trap

Auth JWT in localStorage. Stuffing 4KB of prefs into cookies so every image request carries them. Assuming sessionStorage survives a new tab.
