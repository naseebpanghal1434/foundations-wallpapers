DSAGreedy reach · or DP

The farthest you can still reach.

Jump I: track farthest = max(farthest, i+a[i]). If i > farthest you’re stuck. Jump II: when i hits the layer end, jumps++, end = farthest.

Boolean · one number

Reach

[2,3,1,1,4] i=0 far=2 i=1 far=max(2,1+3)=4 4 ≥ n-1 yes [3,2,1,0,4] far sticks at 3 i=4 > 3 stuck a[n-1]=0 is still success — you're already there

If i ever sits past farthest, a 0 (or a gap) cut you off. One scan, one integer.

vs

Min jumps · BFS layers

Jump II

[2,3,1,1,4] → 2 jumps layers [0] | [1,2] | [3,4] end=0 far=0 jumps=0 i=0: far=2, i==end → jumps=1, end=2 i=1: far=4 i=2: far=4, i==end → jumps=2, end=4 stop at n-2 DP min-jumps O(n²) works; greedy is expected

You do not pick a landing until the layer ends. Updating end every i is the bug.

What

I is one integer — farthest. II is BFS layers: you don’t pick a landing until the current layer is exhausted.

Why

LeetCode 55 / 45. Any index ≤ farthest is reachable, so only the max launch from that prefix matters.

Trap

DFS of every jump — exponential. Updating end every i. Treating a[n-1]=0 as failure: you’re already there.
