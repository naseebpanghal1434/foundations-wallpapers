DSAOverlapping subproblems

Recursion plus memory. That's DP.

Dynamic programming is not a mystic table. You write a recurrence, you notice the same subproblem shows up more than once, you remember the answer. Top-down: memo on the recursive function. Bottom-up: fill an array in order. Time = number of states × work per state. No overlap? That’s just recursion.

1

Write the recurrencefib(n) = fib(n-1) + fib(n-2). Base: 0, 1. Climbing stairs, house robber, coin change — same shape.

recurrence
2

See the overlapfib(5) computes fib(3) twice, fib(2) many times. Merge sort’s halves do not overlap. That’s the test.

overlap
3

Remember itmemo[n] or dp[i]. n states → O(n). 2D: dp[i][j], O(n·m). If you cannot name the state, you cannot DP it.

memory
What

Two ingredients: overlapping subproblems + optimal substructure (best of n is built from best of smaller). Memo and tabulation are the same DAG of states; one starts at the top. Space can often drop to the last row / two variables (fib).

Why

Naive recursion is exponential because it redoes work. Interviews: say the state, the transition, the base, the order. “I’ll memoize” is not a plan until you can write dp[…].

Trap

Calling all recursion DP. Tree recursion with independent halves (merge sort, most divide-and-conquer) has no overlap — memo does nothing. Also: DP-ing a greedy problem, or filling a table without a recurrence you could recurse.
