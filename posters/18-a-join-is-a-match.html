DatabaseINNER · LEFT · CROSS

A JOIN is a match.

A JOIN is a set match on a predicate, usually o.user_id = u.id. INNER drops non-matches. LEFT keeps left rows and fills right columns with NULL. Missing ON (FROM a, b) is a cartesian product: n × m rows. Planner picks Nested Loop / Hash / Merge (plate 98).

CROSS

FROM users, orders -- 3 × 2 = 6 rows -- most pairs are nonsense WHERE on a LEFT JOIN (o.id IS NOT NULL) turns it back into INNER

Always write ON (or USING). Filter left-only rows in WHERE, not in ON, if you meant LEFT.

What

Match condition in ON. INNER = matches only. LEFT = keep left. The match column is usually the FK (plate 17).

Why

Names next to orders without N+1 loops (plate 10). Nested Loop + index on the inner key is the usual plan.

Trap

JOIN then distinct in JS. Duplicate Ada rows are correct 1:N. SELECT * FROM users, orders WHERE users.id = 7 still multiplies orders. Filtering the right table in WHERE on a LEFT JOIN drops the NULLs.
