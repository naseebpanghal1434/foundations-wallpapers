LanguageSRP = one actor

One reason to change.

SOLID is five design constraints. SRP (Single Responsibility): a module has one reason to change — one actor who would request an edit. A class that charges a card, writes a PDF, and emails finance has three actors, so three reasons. Not “one method per file.” Interviews start with S because the God class fails the rest too.

S

One actor

Payroll rules ≠ PDF layout. Split the God class by who asks you to edit it.

O

Extend

Open for extension, closed for edits. New type, not another if in the switch.

L

Substitute

Subtype honors the parent. Square is not a Rectangle (plate 66).

I

Thin iface

Don’t force unused methods. Many small interfaces, not one fat one.

D

Inject

Depend on an abstraction. new Stripe() inside the class is the smell.

What

S = one actor, not one function. O = add a plugin (polymorphism, plate 65). L = is-a for real. I = no kitchen-sink interface. D = inject the mailer; the module does not construct its world.

Why

God classes collect merge conflicts and bugs. SDE 1/2: define SRP with an example, sketch the other four in a sentence, say when you’d skip them (a 30-line script).

Trap

Order that validates, charges, emails, PDFs, and ticks inventory. SRP as “one function per file.” Applying all of SOLID to a weekend script.
