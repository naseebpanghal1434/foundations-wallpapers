Toolsfd 1 · fd 2 · pipes

stdout is data. stderr is diagnostics.

fd 1 stdout is the payload another program should consume. fd 2 stderr is logs, progress, errors — it should survive a pipe. cmd | jq sends only stdout; 2>/dev/null hides errors, not data; the exit code (plate 369) is the third channel.

Keep them split

Two fds

printf("row\n"); /* fd 1 */ fprintf(stderr, "n=12\n"); /* fd 2 */ cmd | jq jq sees only stdout log still on the tty

Progress bars belong on stderr so | gzip stays valid bytes.

vs

Merge into the pipe

2>&1

cmd 2>&1 | tee run.log fd 2 copied onto fd 1 mix of data + logs >/dev/null silences 1, not 2

Both are ordinary fds (plate 294). The split is convention, not kernel law.

What

Two streams by convention. stdout is the pipeline payload; stderr is diagnostics that should outlive a redirect of fd 1.

Why

Pipelines, CI logs. “Broken pipe” is SIGPIPE on stdout when the reader closed (exit 141).

Trap

JSON on stderr and errors on stdout, then parsing the mix. >/dev/null and wondering where the error went — it is still on 2.
