FrontendThrow a promise · fallback

Suspense is a pause, not a spinner.

Suspense is a boundary: if a child isn’t ready, React paints fallback and retries when the promise resolves. The child throws a promise (or a framework hook does); it is not a spinner you mount yourself.

1

Child isn’t readylazy(() => import('./Chart')) — the child throws a promise. Code-split and data both sit here.

Boundary paints fallback<Suspense fallback={…}><Chart/></Suspense>. First paint is the placeholder, not a <Spinner/> you mounted.

Promise resolves, retryModule loads, Chart commits. Data Suspense needs a cache the child reads. Two siblings that each suspend waterfall unless you prefetch.

What

A boundary around async UI. Fallback is the placeholder. Errors belong in an error boundary, not Suspense.

Why

React 18 interviews. “How does lazy work?” is this plate. Streaming SSR sits on the same pause.

Trap

Suspense around the whole app — one slow widget blanks everything. Using it as a loading boolean. No error boundary, so a failed fetch is an uncaught throw.
