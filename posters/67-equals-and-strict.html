FrontendECMA-262 · ToNumber

== converts. === does not.

=== is Strict Equality: same Type, then same value. == is Abstract Equality — ToPrimitive / ToNumber until types match. ToNumber("") is 0, so 0 == "" is true. Objects compare by reference on both. Default to ===; the one useful == is x == null (null and undefined only).

Abstract Equality

==

0 == "" true 0 == "0" true "" == "0" false null == undefined true null == 0 false [] == 0 true

Not transitive. [] ToPrimitive → "" → ToNumber 0.

vs

Strict Equality

===

0 === "" false null === undefined false NaN === NaN false {n:1} === {n:1} false p === p true

Object.is is === except NaN (true) and +0/-0 (false).

What

Different types → == coerces; === is false. Two heap objects with the same fields are still two pointers (plate 69). NaN === NaN is false; use Number.isNaN or Object.is.

Why

if (count == "") is true when count is 0. Auth and form code die here. Interviews put the table on the board.

Trap

== with 0 / "" / false / []. Expecting {n:1} === {n:1} to be true. Compare an id, or a real deep equal.
