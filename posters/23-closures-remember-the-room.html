A closure remembers the room.

A closure is a function plus the variables it could see when it was created. The outer function can return; those variables still live as long as the inner function does.

makeCounter() returns inner

Still sees count

function makeCounter() { let count = 0 return () => ++count } const a = makeCounter() a() // 1 a() // 2 count is private to a

Each call to makeCounter gets its own count. a and b do not share.

var in a for-loop of handlers

One i, late

for (var i = 0; i < 3; i++) { btns[i].onclick = () => alert(i) } // every button alerts 3

They closed over the same i, read later. let in the loop gives each iteration its own i.

What

Inner function can use outer locals after the outer call has finished. That’s a closure. It’s how modules, React hooks, and private state work in JS.

Why

Interviewers use it to see if you know when the variable is read (later) vs copied (never, unless you bind a snapshot). Hooks: each render’s functions close over that render’s props/state.

Trap

Thinking the value is copied at creation. It isn’t — it’s a live binding. Also: stale closures in setInterval / useEffect that captured an old count.
