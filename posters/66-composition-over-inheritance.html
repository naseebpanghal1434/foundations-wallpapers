Languageextends vs a field

Has-a beats is-a.

Inheritance is is-a: a subtype must honor the parent contract at every call site (Liskov, plate 72). Composition is has-a: a field plus forwarding. class User extends Array reuses push by claiming a user is a list. Hold roles = [] instead. Java’s Stack extends Vector is the same false is-a.

Reuse by extending

False is-a

class User extends Array {} u.push(role) u.map(fn) // not a User class Square extends Rect { setWidth(w) { this.w = this.h = w } } // caller set 4×5, Square is 5×5

A User is not an Array. A Square is not a Rect you can stretch on one axis.

vs

Reuse by holding

Has-a

class User { roles = [] } class Square { size } class Rect { w, h } // both: area() // neither extends the other

Share an interface if you need polymorphism (plate 65). Do not inherit for the methods.

What

Composition = fields + delegation. Inherit only when substitution is true. JS extends Array also breaks map species and JSON.stringify.

Why

A change in the base class hits every subclass. A field you own can be swapped. Interviews: Square/Rectangle, then User-extends-Array.

Trap

User extends Array or Stack extends Vector for a few methods. If you cannot say “is-a” as a type fact, do not extends.
