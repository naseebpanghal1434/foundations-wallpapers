DSALRU node · two links

Prev makes splice O(1).

A doubly-linked node has prev and next. If you already hold the node, unlink is four pointer writes — O(1), no scan. LRU cache is a hashmap from key to node plus this list for recency. The map finds; the list splices.

Two sentinelsdummyH ⇄ A ⇄ B ⇄ C ⇄ dummyT. Head and tail are never null, so every real node has two neighbors. Least-recent sits after dummyH.

recency
What

Four links to cut a node (its neighbors and its own prev/next). O(1) only if you have the node. Finding by value is still O(n) — that is why LRU pairs the list with a hash map (plate 150).

Why

LRU, LFU’s recency list, browser history, deque internals. Interview design: “O(1) get and put” forces hash + DLL. Say both.

Trap

Forgetting to update both directions — a one-way splice corrupts the list. Deleting while iterating without saving next. Using a singly list for LRU and scanning for the victim — that’s O(n), not O(1).
