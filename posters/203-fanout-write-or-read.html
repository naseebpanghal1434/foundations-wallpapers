SystemFollowers · celebrity problem

Fan-out on write, or on read.

A post with N followers is N inbox writes at post time, or a fan-in of followees at read time. A celebrity with 80M followers is 80M Redis LPUSHes — a stampede (plate 94). Hybrid: push if N < 100k, pull the famous.

Precompute every inbox

Fan-out write

POST /tweet worker: LPUSH tl:u tweetId × N followers home = LRANGE 0 49 80M fans = 80M writes on one post

Fine for a 200-follower account. One celebrity post is 80M Redis ops. Never on the POST thread.

vs

Push small · pull famous

Hybrid

N < 100_000 queue LPUSH inbox N ≥ 100_000 celeb’s own store home = mix (plate 204) POST commits the row fan-out is a job

Notifications are the same fork (plate 205). Backpressure the worker; do not 80M-write the request.

What

Write-fanout precomputes the feed. Read-fanout computes it on request (fan-in from followees). Hybrid is the answer at Twitter scale: queue the fan-out.

Why

Twitter / Instagram design. The celebrity problem is the interview — say hybrid in the first minute, with the 80M write cost.

Trap

Always fan-out on write. 80M LPUSH on the request with no worker. No backpressure. Treating followers as a SQL IN at read with no cache.
