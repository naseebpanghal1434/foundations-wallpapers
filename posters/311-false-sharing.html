ArchMESI · ping-pong

False sharing is two cores, one line.

Two cores write adjacent fields that sit in the same 64 B line. The line bounces Exclusive↔Modified (MESI) even though the programmers never shared a variable. Symptom: linear slowdown with cores, high cache-coherence traffic, low actual work.

Eight counters, one line

Ping-pong

struct { atomic n[8]; } 8 × 4 B = 32 B < 64 B 8 cores write “their” n[i] line Exclusive ↔ Modified

No software sharing. Still hardware sharing. perf c2c / mem events.

vs

Pad to the line

alignas(64)

alignas(64) atomic n; one counter per 64 B Go padded structs Java @Contended

Coherence is per 64 B line (plate 309). False = you did not share a variable.

What

Coherence is per line. False sharing: no software sharing, still hardware sharing.

Why

A per-core counter array without padding is slower than a mutex at N=8.

Trap

Array of 4-byte atomics. “But they are different variables.” They are not different lines.
