Toolsexecve · /usr/bin/env

#! is the kernel's interpreter line.

execve on a file starting #!/usr/bin/python3 rewrites to execve("/usr/bin/python3", ["python3", script, args]) — the kernel does this, not the shell. #!/usr/bin/env python3 looks up PATH; the file needs chmod +x. A CRLF after python3 yields “interpreter not found.”

./app.py · kernel rewrite

shebang

#!/usr/bin/env python3 chmod +x ./app.py ./app.py a b execve env → python3 argv: python3 ./app.py a b

Linux shebang length cap ~127–256 bytes. env -S splits extra args on some systems.

vs

python3 app.py · comment

skipped

python3 app.py a b #! is a Python comment no +x required no PATH lookup of env works here, fails as ./

Portable scripts use env. Nix/Guix often pin an absolute interpreter path.

What

A tiny exec protocol: first line names the interpreter. The kernel, not bash, performs the rewrite.

Why

CLI tools, Docker ENTRYPOINT. Why it “works as python3 x.py” and not as ./x.py.

Trap

Windows CRLF (python3\r is ENOENT). Spaces in the interpreter path. Relying on python not python3.
