DSALower bound · upper bound

The first true. The last true.

Binary search on a sorted array with duplicates: lower bound = first index where a[i] ≥ x (first true). Upper bound = first index where a[i] > x. Last occurrence is upper−1 if that slot equals x. The predicate must be monotonic: false, false, …, true, true.

a=[1,2,2,2,4] · x=2

Two bounds

while lo < hi: # hi exclusive mid = (lo+hi)//2 # first ≥ x (lower) → 1 if a[mid] >= x: hi=mid else: lo=mid+1 # first > x (upper) if a[mid] <= x: lo=mid+1 else: hi=mid last = lo-1 → 3

Count of x is last−first+1, or 0 if missing. Pick a template and an invariant (plate 53).

trap

Any match, then walk

Scan out

if a[mid] == x: while i-1 >= 0 and a[i-1]==x: i -= 1 # first while j+1 < n and a[j+1]==x: j += 1 # last # all equal → O(n) # they asked O(log n)

Classic bisect returns any hit. First/last are two searches, both log n. lo = mid on a 2-range must still make progress.

What

Two binary searches, O(log n). Unsorted: cannot. Same first-true template as first bad version and as “minimum capacity that works” (plate 142). Insertion position is lower bound of x.

Why

LeetCode 34. The screen after “can you binary search”: they want the left edge and the right edge, not a lucky mid. Say the predicate out loud: ≥ x, then > x.

Trap

Returning any match. Infinite loop: lo = mid on a two-length range. Checking a[mid]==x and scanning outward — O(n) on an all-equal array. Mixing hi = mid with hi = mid-1 across the two searches.
