DSAPush/pop front and back

Both ends are doors.

A deque (double-ended queue) pushes and pops at both ends in O(1). Sliding-window maximum keeps candidates in a deque of indices, front = max (plate 136). Palindrome check: pop both ends. Implement a queue with a ring, or two stacks — different trade.

One door · LIFO

Stack

push/pop same end 1 2 3 → pop 3

Undo, brackets, DFS. Not both ends.

In back · out front

Queue

enq 1 2 3 deq → 1 2 3

BFS, level order. One way in, one way out.

Both ends · O(1)

Deque

k=3 [1, 3, -1, -3, 5] dq decreasing, front=max [1,3,-1] 3 [3,-1,-3] 3 [-1,-3,5] 5

Windows: 3, 3, 5. Drop stale indices from the front; pop smaller backs.

What

O(1) push/pop front and back. Random access is not promised (a ring deque can index; a linked deque cannot cheaply). Python collections.deque, Java ArrayDeque.

Why

Sliding window max/min, 0-1 BFS (push front if weight 0), palindrome, undo/redo with two ends. When both ends move, it is a deque not a stack.

Trap

Java Stack class (synchronized, extends Vector) vs ArrayDeque. Indexing a linked deque as if it were an array. Using deque as a list and scanning the middle — O(n).
