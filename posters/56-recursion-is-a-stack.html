DSABase case first

Recursion is a stack.

Each call pushes a frame: locals, arguments, return address. The base case pops back. No base case — or a problem that never shrinks — and the stack grows until it dies. Recursion is not magic. It is a stack you don’t see.

Shrinks · then returns

Base case

function fact(n) { if (n <= 1) return 1 return n * fact(n-1) } fact(3) fact(2) fact(1) → 1 2*1 → 2 3*2 → 6

Active frame on top. Finite depth. Trees: DFS is this stack, or an explicit one (plate 52).

trap

Never stops shrinking — or never shrinks

Overflow

function fact(n) { return n * fact(n-1) } // fact(3) → fact(2) → … → boom function f(n) { return f(n) // same n }

Stack overflow / RecursionError. Python ~1000 frames. A 10⁵-node list: iterate.

What

Base case + smaller subproblem. Space is O(depth). Tail-call elimination is not in Python or JS — return fact(n-1) still grows the stack. Memo turns tree recursion (fib) from exponential into O(n).

Why

Write the base case first, then the recursive step, then name the overflow. Interviews: reverse a list, tree walks, backtracking. Anything you recurse, you can push onto an explicit stack.

Trap

Missing base case. Recursing on the same n. Two recursive calls with no memo (fib). Deep linked-list recursion on 10⁵ nodes — O(n) frames, crash; the iterative reverse is O(1) extra.
