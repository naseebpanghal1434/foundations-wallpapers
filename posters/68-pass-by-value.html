LanguageThe pointer is copied

Pass the reference by value.

Java, JavaScript, and Python copy the argument into the parameter slot. A number copies the bits. An object copies the pointer. user = { name: "Kai" } rebinds that slot; the caller’s binding is unchanged. user.name = "Kai" mutates the shared heap object. That is pass-by-value of a reference — not C++ T&, which would update the caller’s name.

Rebind the parameter

Caller unchanged

function rebind(user) { user = { name: "Kai" } } let ada = { name: "Ada" } rebind(ada) ada.name // "Ada"

The slot named user got a new pointer. ada still points at Ada.

vs

Mutate through it

Same object

function mutate(user) { user.name = "Kai" } mutate(ada) ada.name // "Kai"

Two names, one heap object (plate 69). Field writes are visible. Still not pass-by-reference.

What

Every call copies the value in the argument slot. Object values are references. Pass-by-reference would mean user = … updates the caller (C++ T&, or a pointer-to-pointer in C).

Why

The whiteboard is two arrows: one copied pointer, one object. Rebind vs mutate is the whole question.

Trap

Saying “JS is pass-by-reference” because mutation is visible. If it were, rebind would rename Ada. Also: mutating a shared object you thought you had copied (plate 71).
