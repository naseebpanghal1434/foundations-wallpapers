SystemHeartbeat · last-seen

Presence is a TTL, not a boolean.

Online is SET user:42:online EX 30, refreshed every 10 s — the same Redis TTL pattern as INCR+EXPIRE (plate 201). Miss 3 beats → expire → offline. last_seen is the stamp you show. onclose does not fire on lid close or half-open TCP.

WS close never fires

Boolean

UPDATE users SET is_online = true WHERE id = 42 onclose → is_online = false -- lid, killed tab, -- half-open TCP: never

A green dot that never turns off. Trusting onclose is the bug. The socket map (plate 216) uses the same TTL.

vs

Heartbeat · EX 30s

TTL

SET user:42:online EX 30 refresh every 10s miss 3 beats → expire last_seen = now pub online on first SET offline on EXPIRE

“Last seen 3m ago” beats a lying green dot. Mobile: longer TTL (45–60 s). No graceful close required. Keyspace notify or a scanner for expiry.

What

Expiry is the source of truth: connect starts the TTL, heartbeat refreshes, expiry is offline. Presence channel: pub on first SET, offline on expire.

Why

Chat, docs, games. Interviewers wait for you to distrust onclose.

Trap

Boolean column. Trusting onclose. Heartbeat every 50 ms × 1M users. Scanning the whole user table for last_seen < now()-30s every second without an index / Redis.
