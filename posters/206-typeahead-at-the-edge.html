SystemPrefix · cache · 50ms

Typeahead is a trie at the edge.

Autocomplete is prefix lookup with p99 ≤ 50 ms. A trie (plate 62) or completion index, cached at the edge (CDN / Redis) — not Postgres on every keystroke. Debounce 30–50 ms (plate 24). Rank top 10 by popularity; personalize is a rerank of those 10.

Origin per key

LIKE

SELECT name WHERE name LIKE 'jo%' -- every keystroke origin 80–120ms 10 keys = 10 hits p99 > 50ms

Prefix jo% can use a B-tree. The crime is the RTT. Leading %jo% cannot use the index (plate 02).

vs

Hot prefixes nearby

Edge + trie

debounce 40ms GET prefix:jo CDN / Redis → 10 MISS → trie / ES off-peak rebuild budget 50ms

jo is a tiny keyspace — cache it. A new famous name refreshes that prefix, not the world. This is not a search page (plate 217).

What

Prefix data structure + aggressive cache + client debounce. Results are 8–10 hits. Invalidation is per-prefix, not a global flush.

Why

Typeahead / search-as-you-type. Latency is the product. They want a trie or completion suggester, p99 ≤ 50 ms, not LIKE.

Trap

LIKE '%jo%' (leading wildcard). Hitting origin on every key. Returning 1000 hits. No debounce so 10 requests per word.
