SystemSigned URL · object store

The API does not hold the file.

Bytes never stream through API RAM. POST /uploads mints a signed PUT to S3/GCS (X-Amz-Expires=900 — 15 min). Client PUTs; you store key, size, hash. Download: sign GET at read (Expires=300) or a CDN — never persist the signed URL as the permalink.

Commit metadata; sign at readWebhook / complete → DB: key, size, sha256, CDN path. GET: mint Expires=300 (5 min). Eternal signed URLs are a leak.

What

Metadata in the DB, bytes in object storage, hot reads on a CDN (plate 36). The signature is auth and a TTL. Sign again at read; the URL is not the public id.

Why

Dropbox / YouTube-upload / avatar. They want: your RAM is not a disk. Direct-to-blob plus a 15-minute PUT expiry is the move.

Trap

multipart/form-data through Node into /tmp. Files on the app instance. Eternal signed URLs. Trusting client Content-Length with no cap.
