NetworkIf-None-Match · validators

304 is not a body.

304 Not Modified means use what you cached. There is no payload — it is a successful revalidation after If-None-Match or If-Modified-Since (plate 245).

Every time

200 full

GET /app.js 200 180KB GET /app.js 200 180KB again no validator, no 304

CDNs cannot 304 if origin never sends ETag or Last-Modified. Parsing 304 as JSON is undefined.

vs

Conditional GET

Then 304

GET /app.js 200 ETag: "abc" If-None-Match: "abc" 304 (no body) cache keeps bytes

304 is not 204. 204 No Content is a real empty success for an action. 304 is cache protocol.

What

Conditional GET. Validators live on the representation. 304 must not include a body per spec.

Why

Repeat views, API clients with caches, CDNs. Bandwidth that is not in your origin graph.

Trap

fetch().json() on a 304. Origin that never sends ETag/Last-Modified. Using 304 for a POST.
