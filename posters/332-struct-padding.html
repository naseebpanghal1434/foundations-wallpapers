Langsizeof · offsetof

The compiler inserts padding for alignment.

struct { char c; int32_t x; } is 8 bytes, not 5: 3 pad so x sits at offset 4 (plate 320). Order fields decreasing size to shrink. packed removes pad and may split loads. JSON and protobuf do not use C layout.

char then int32 · not 5

sizeof 8

offset 0 c 1–3 pad 4–7 x alignof = 4 offsetof(x) = 4 64-bit ptr = 8

Natural align = size. An unaligned int32 splits the load (plate 320).

vs

int32 then char · still 8

Tail pad

offset 0–3 x 4 c 5–7 pad struct align = max member array[N] = N×8

C does not reorder fields. Java/Go may. packed is a wire format, not a hot in-memory layout.

What

ABI layout: sizeof, alignof, offsetof. An array of structs multiplies the padding. Cache-line packing is 64 B (plate 309).

Why

Wire vs in-memory. A 1-byte flag next to a pointer is 1+7+8 on SysV AMD64. Measure with sizeof, not by adding field sizes.

Trap

fwrite(&s, sizeof s, 1, f) as a file format (pad, endian, align). memcmp of structs — padding bytes are garbage. Then “it failed on the other compiler.”
