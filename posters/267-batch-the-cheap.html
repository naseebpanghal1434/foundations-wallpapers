GenAIEmbeddings · throughput

Batch the cheap calls.

Embeddings and classifiers love a batch: one kernel, many inputs. Decode is pickier — different lengths, different KV — so batch offline 32–256; online, a 10–50ms window so you don’t add a beat to TTFT.

One string, one HTTP

1-QPS saw

POST /embed × 1000 calls same model same tokenizer 1000 round trips

Ingest and evals die here. Cost graphs look like a sawtooth of 1-QPS.

vs

One POST · many strings

One kernel

POST /embed [1000 strings] sort by length pad = longest in this batch

Huge pads waste. Don’t mix models. Don’t batch interactive chat if it delays first token.

What

Throughput vs latency. Batch what is embarrassingly parallel. Same model, same tokenizer, sort by length.

Why

Ingest pipelines, evals, backfills. The cheap calls are embeddings and classification, not user chat.

Trap

Batching 1. Padding a 4-token query to 8k. Mixing models in one batch.
