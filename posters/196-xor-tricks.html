DSAa^a=0 · a^0=a

XOR cancels pairs.

XOR is bitwise add without carry. a^a=0, a^0=a, commutative, associative. Single number: XOR the array, pairs die, the lonely remains. Two singles: XOR all, a bit that is 1 belongs to one of them — split the array by that bit, XOR each half. Missing number: XOR indices and values. Swap without temp: a^=b; b^=a; a^=b — cute, rarely wise.

Pairs vanish

One single

[2,2,1] 2^2^1 = 0^1 = 1 every pair → 0 lonely → itself

LC 136. Linear, O(1) extra. Proof needs exactly pairs plus one.

[1,2,1,3,2,5] xor=3^5=6 (110) last set bit = 2 bit set: 2,3,2 → 3 bit clear: 1,1,5 → 5

LC 260. The set bit is where the two singles differ.

136's proof dies on triples: count each bit % 3 (LC 137) missing 0..n: xor i with a[i] n&(n-1) drops a 1

LC 268 / 191 / 338. Bits independent. dp[i]=dp[i>>1]+(i&1).

What

Linear time, O(1) extra for these. Not a search. Bits independent — you can count or XOR them one column at a time. Two singles need a splitting bit; triples need mod 3 (or a two-bit FSM), not another XOR.

Why

LeetCode 136 / 137 / 260 / 268 / 191. Bit screens. 137 is the follow-up that breaks 136’s proof. Say a^a=0 before you write the loop.

Trap

XOR for sums (that’s +). Assuming XOR isolates a value that appears 3 times — 136 needs exactly pairs. Overflow on 1<<31 in Java: use >>> or 1L. The temp-less swap overlapping the same variable.
