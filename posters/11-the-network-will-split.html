SystemCAP · quorum · PACELC

The network will split.

A partition is packet loss, a dead switch, or a GC pause that looks like death (timeout 1–5 s). During that split a replica can wait/error to stay linearizable (CP) or answer with a stale or divergent value (AP). Both for the same object is impossible. PACELC: even without a split you still trade latency vs consistency.

Majority or error

etcd / ZooKeeper / Raft write if n/2+1 ack else timeout / 503 Postgres sync replica: COMMIT waits for flush or fails the write linearizable read: quorum, not the nearest

AP

Cassandra / Dynamo / DNS W=1 R=1: always a reply may read a stale version LWW or vector clocks on the way back DNS TTL (plate 278): wrong for minutes

Some answers conflict. DNS is the everyday AP system.

What

P is given. C = every read sees the latest committed write. A = every request gets a non-error. During P, C and A cannot both hold.

Why

Multi-AZ writer: fail the write (RDS Multi-AZ) or accept on both sides (multi-master) and merge. Interviews: name a CP system and an AP system.

Trap

“We’ll pick CA and skip P.” Two nodes, no quorum, both accept writes → two values for k (split-brain). Replicas of a primary are not AP — writes still need the primary.
