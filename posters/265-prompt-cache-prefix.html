GenAIStable prefix · KV

Prompt cache is prefix reuse.

If the first N tokens match across requests, a provider can reuse the KV (plate 254) — cheaper, faster. The prefix must be byte-stable; put the volatile user question last.

Clock in the system prompt

Never hits

system: 2026-08-26T… tools shuffled req_id=… one token at pos 0 → full miss

A one-token change at position 0 invalidates the whole prefix.

vs

Static head · user last

Byte-stable

[tools + policy] [docs / RAG header] [user question] same bytes, same KV

Some APIs need a minimum prefix length. This is not a RAG embedding cache.

What

Cache the stable head. Dynamic content goes last. Same reason CDNs like immutable URLs.

Why

Cost and TTFT on a busy copilot. Identical system + tools + schema is the hit; the question is the miss by design.

Trap

ISO timestamps and request ids in the system message. Reordering tools every call. Caching a prefix that includes the user’s PII.
