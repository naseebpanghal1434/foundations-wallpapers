SystemFrontier · robots.txt · politeness

A crawler is polite BFS.

A crawler is BFS over URLs (plate 59) with a per-host cap: robots.txt, 1 in-flight per host, Crawl-delay, honor 429 + Retry-After. Frontier = priority queue. Seen = Bloom + store (plate 123). Recrawl by change-rate, not daily-all.

Rude recursion

DFS scrape

scrape(url): GET url no delay for link: scrape(link) ignore robots.txt ?session= is “new” one global QPS DDoS the small host

DFS blows the stack and the host. Querystrings are not pages. A global QPS still flattens one origin.

vs

Frontier + cap

Polite BFS

frontier = PQ seen = Bloom + KV pop url robots? delay? 1 in-flight / host 429 → Retry-After normalize → enqueue

Normalize: lowercase host, strip tracking params, pick canonical. Seed sitemaps. Cache DNS and robots per host.

What

Frontier + seen + fetcher + parser + store. Politeness is 1 in-flight per host plus crawl-delay. Respect 429 the same way a client respects a rate limiter (plate 201).

Why

Web crawler / search-indexer design. Politeness is the interview, not the HTTP GET.

Trap

DFS recursion. No seen-set → infinite calendar links. Crawling ?session= as unique. One global QPS. Ignoring robots.txt and 429.
