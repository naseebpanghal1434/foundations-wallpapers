DSASearch vs extract-min

A BST finds. A heap pops min.

A BST is an ordered map: left < node < right. Search, insert, floor, ceil, range — walk a path. A heap is a priority queue: parent ≤ children (min-heap). Extract-min is cheap. “Is 6 in here?” is a scan. They are not interchangeable trees.

Left < node < right

BST

8 3 10 1 6 find 6: 8 → 3 → 6 inorder: 1 3 6 8 10 (plate 57)

Path of length height. Balanced (AVL / red-black / TreeMap): O(log n). Sorted inserts with no balance: a linked list.

vs

Parent ≤ kids · array

Heap

[1, 3, 2, 8, 6, 10] min is index 0 pop → heapify O(log n) find 6 → scan O(n) left/right not ordered

Complete tree, so always bushy. Kids at 2i+1, 2i+2. Fast min/max. No binary search, no inorder.

What

BST = ordered set/map (predecessor, range). Heap = priority queue (plate 63). Hash set beats both for “is it here?” if you don’t need order or min. Java: TreeMap vs PriorityQueue.

Why

Interview fork: “next meeting / autocomplete keys” → BST (or trie, plate 62). “always the smallest deadline / k largest” → heap. Draw the invariant, not the picture of a tree.

Trap

A heap for arbitrary lookup (“binary search the heap”). A raw BST after inserting 1..n — height n, search is O(n). “BST is always log n” is the same lie as “quicksort is always n log n” (plate 64).
