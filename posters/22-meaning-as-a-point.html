Gen AIEmbeddings

Meaning as a point in space.

An embedding turns a sentence into a list of numbers — a point. Sentences with similar meaning sit near each other. RAG search is “nearest neighbors,” not Ctrl+F. “How do I reset my password?” can match “account recovery steps.”

Keyword search

Ctrl+F

query: "reset password" misses: "account recovery" misses: "forgot login"

Needs the same words. Synonyms fail. Typos fail. Meaning is ignored.

vs

Vector search

Near

"reset password" · · "account recovery" · · close "forgot login" · "shipping rates" far

Same embedding model for docs and query. Distance ≈ meaning.

What

A model maps text → a vector (e.g. 768 or 1536 numbers). You store vectors in a vector DB. At query time you embed the question and take the closest chunks, then paste them into the LLM prompt (plate 12).

Why

Users don’t type your docs’ headings. Semantic search finds “the bit about refunds” even when they said “I want my money back.” That’s the retrieval in RAG.

Trap

Embedding with model A and querying with model B — the spaces don’t match. Or embedding 50-page blobs; retrieve small chunks (a heading + a paragraph), not whole PDFs.

Search by meaning, not by matching letters. Near in space ≈ near in sense.
