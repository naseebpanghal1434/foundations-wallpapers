FrontendMicrotask · macrotask

Promises drain before timers.

Promise.then, queueMicrotask, MutationObserver are microtasks; setTimeout, I/O, and events are macrotasks. After every stack the engine drains the whole microtask queue before the next macrotask or paint.

then vs timeout 0

1, then 2, then 3

console.log(1) Promise.resolve().then(() => console.log(2)) setTimeout(() => console.log(3), 0) // prints 1, 2, 3

await after the first line is a microtask. fetch’s callback is a macrotask wrapping a microtask.

drain

then queues another then

Still before timer

.then(() => { console.log(2) Promise.resolve().then(() => console.log(2b)) }) setTimeout(() => console.log(3), 0) // 1, 2, 2b, then 3

The drain includes microtasks scheduled during the drain. Then render may happen.

What

Macrotask: one per turn. Microtasks: all of them, including ones queued during the drain. Then render may happen.

Why

The classic interview order question. A tight promise loop can starve paint just like a busy stack (plate 226).

Trap

Assuming setTimeout(0) beats Promise.then. Recursing promises until the tab janks. Mixing Node nextTick (micro) with setImmediate (macro) as if they were the same.
