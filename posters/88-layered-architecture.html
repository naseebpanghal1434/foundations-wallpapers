Backendhandler → domain → repo

The route does not speak SQL.

Three layers. The handler parses HTTP and returns status codes. The domain runs placeOrder() with no req and no SQL. The repository is the only place for SELECT / INSERT. SQL in app.post('/orders', …) couples Express to Postgres in one function — untestable, and the next endpoint copies it.

HTTP

Parse the request. Status codes. Authn/authz at the edge (plate 14). Knows req / res. Does not know SELECT.

handler

calls
Domain

placeOrder(). refund(). “May this user, this row, this action?” No Express. No pg. The product lives here.

Repo

SELECT / INSERT. Returns objects, not rows to the route. The only layer allowed to speak the database.

SQL

What

Handler → domain → repository. Dependencies point inward: HTTP knows domain, domain knows a repo interface, repo knows Postgres. This is the SDE-sized slice of hexagonal / clean architecture.

Why

Unit-test placeOrder with a fake repo (plate 89). Change the URL without rewriting money rules. One place for “can this user refund?”

Trap

app.post('/orders', (req, res) => db.query(...)). Domain importing Express. Passing req into the repo. A “service” that only forwards arguments.
