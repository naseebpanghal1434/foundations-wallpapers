LangSysV · Win64 · aapcs

ABI is which register is arg0.

Application Binary Interface: sizes, alignment, who saves which register, how a struct is returned, how syscalls look. SysV AMD64: arg0=rdi, 1=rsi, 2=rdx, 3=rcx, 4=r8, 5=r9, rest on the stack; return rax. Win64: rcx rdx r8 r9. Mix two ABIs in one process = corruption.

SysV AMD64 · Linux / macOS

rdi = arg0

write(fd, buf, n) rdi fd arg0 rsi buf arg1 rdx n arg2 rcx r8 r9 3..5 stack 6+ return rax

8-byte slots. 16-byte RSP alignment at the call. aapcs64: x0–x7.

vs

Win64 · MSVC

rcx = arg0

WriteFile(h, buf, n) rcx handle arg0 rdx buf arg1 r8 n arg2 r9 arg3 32 B shadow home return rax

extern "C" kills C++ name mangling, not the register contract.

What

The calling convention plus type layout. Compilers on one platform agree so .o files combine (plate 325). Caller- vs callee-saved, struct return in rax or a hidden pointer.

Why

FFI, assembly, kernel ABI vs user. Why an MSVC C library may not link with MinGW. Linux syscalls use the same SysV regs except r10 in place of rcx.

Trap

Passing a Go string (ptr+len, two words) to a C char* as if it were one pointer. Forgetting the 16-byte stack alignment and crashing in an XMM spill.
