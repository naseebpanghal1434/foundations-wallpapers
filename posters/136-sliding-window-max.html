DSAMonotonic deque · O(n)

The deque front is the max.

Sliding window maximum: for every window of k, the max. Heap of k is O(n log k) and stale indices need lazy skip. Better: a deque of indices, values decreasing. Incoming a[r]: pop back while smaller (they will never be max). Pop front if it left the window. Front is the answer.

Store indices, not values, so you can expire r-k. Window is [r-k+1, r] — drop the front when its index is ≤ r-k.

Window min: increasing deque. Heap also works (lazy stale pops) — O(n log k), not the expected O(n).

What

Monotonic deque (also window min, first negative in window). Store indices not values so you can expire r-k. Plate 108’s both-ends queue: pop back (useless smaller), pop front (out of window), read front (best).

Why

LeetCode 239. Hard-for-SDE1, expected-for-SDE2. Pattern: “candidates in a queue, front is best, back is newest.” Each index is pushed and popped at most once → O(n).

Trap

Storing values so you cannot tell expiry. Heap without checking the index. Nested max() per window — O(nk). Popping the front when it is still inside the window (expire only if index ≤ r-k).
