OSuser · kernel · SYSCALL

A syscall is a trap into the kernel.

User code cannot touch devices or another process’s memory. write, mmap, clone, ioctl enter via SYSCALL/SVC: privilege on, kernel stack, table lookup by number. Linux x86-64: rax = number, rdi rsi rdx r10 r8 r9 = args; return in rax, negative is -errno.

Ring 3 · libc wrapper

User

write(fd, buf, n) rax = 1 SYS_write rdi = fd rsi = buf rdx = n SYSCALL

Ring 0 · sys_call_table

Kernel

copy_from_user file_ops.write rax = n or -errno SYSRET

x86-64 args

r10 not rcx — SYSCALL clobbers rcx.

What

The only legal door user→kernel. Everything else is a library on top.

Why

Why user space cannot bind :80 without CAP_NET_BIND_SERVICE. Why a bad pointer is EFAULT, not a panic.

Trap

Busy-looping instead of a blocking syscall. Assuming gettimeofday always traps (vDSO). Treating errno as process-global — it is per-thread.
