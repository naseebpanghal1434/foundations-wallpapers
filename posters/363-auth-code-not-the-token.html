BackendOAuth 2 · PKCE

The auth code is not the token.

OAuth authorization code flow: the browser gets a short-lived code at the redirect. The backend (client secret or PKCE) exchanges that code at the token endpoint for access (+ refresh). The SPA should not be a confidential client; the access token stays off URL logs.

1

GET /authorize?client_id&redirect&code_challengePKCE: S256 of the verifier. Browser never sees the access token here. Implicit flow is deprecated.

authorize
2

Redirect ?code=One-time ticket, seconds of life, bound to redirect_uri. Not a bearer key. Referrer/logs may see it — that’s why it is short.

code
3

POST /token code + verifier → access_tokenConfidential client: secret on the server. Public/SPA: PKCE, no secret. OpenID adds id_token (validate aud).

token
What

Delegation protocol. Code is a one-time ticket. Bearer token is the key (TLS + storage, plate 232).

Why

Login with Google/GitHub. Why the secret is on the server, not in the SPA bundle.

Trap

Putting the access token in the redirect fragment and calling it modern. Skipping PKCE on public clients. Using the id_token as an API key at your backend without validating aud.
