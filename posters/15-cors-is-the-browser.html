NetworkOrigin · ACAO · OPTIONS

CORS is the browser saying no.

Same-origin = scheme + host + port. A page at https://app.shop.io cannot read https://api.shop.io unless the API sends Access-Control-Allow-Origin matching Origin. curl, servers, and mobile apps skip CORS. Preflight: OPTIONS + Access-Control-Request-Method for non-simple requests.

fetch from app.shop.io

Blocked

GET /me Origin: https://app.shop.io → 200 {"id":42} server ran no Access-Control-Allow-Origin → JS TypeError network tab still 200

The browser hides the body from JS. Cookies still require SameSite + CORS credentials mode.

vs

API opts in · curl does not care

ACAO

Access-Control-Allow-Origin: https://app.shop.io Access-Control-Allow-Credentials: true Vary: Origin curl https://api.shop.io/me 200 — CORS never consulted

Authorization / Content-Type: application/json → OPTIONS first. 204 on the preflight.

What

CORS is a browser read permission, not auth and not a firewall. The handler already ran. Preflight is the browser asking before a “non-simple” request.

Why

Without it, evil.com could fetch your API with cookies (if SameSite allows) and read JSON. Interviews: Origin is not a security boundary for curl.

Trap

ACAO: * plus credentials (browser rejects). “Turn CORS off” in prod. Missing Vary: Origin so a CDN caches the wrong ACAO. Treating CORS as authz (plate 14).
