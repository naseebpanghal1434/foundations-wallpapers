Rate limits are a budget.

A rate limit is tokens per subject per window. Token bucket: capacity C (burst), refill r tokens/s, each request spends 1. Empty bucket → HTTP 429 + Retry-After. Store the bucket in Redis so every replica shares one counter — not RAM per process.

burst C

20 tok

Bucket capacity. A burst of 20 is allowed immediately; then you wait on refill.

refill r

10 /s

tok = min(C, tok + r·Δt). 0 tokens → reject. GCRA / leaky bucket is the dual.

reject

429

Retry-After: 2. X-RateLimit-Limit / Remaining / Reset so honest clients back off.

shared store

INCR

Redis INCR key + EXPIRE (Lua so check+set is one op). Key: user:42:w or api_key.

What

Limit by user id, API key, IP, or route. Fixed window is one INCR; it spikes at the seam (100 at 00:59.9 + 100 at 01:00.0 = 200 in 100 ms). Token bucket / sliding window smooth that. Login is a tighter bucket (credential stuffing).

Why

Protects the DB pool (plate 03) and the bill. System-design interviews almost always include a limiter: where it lives, the key, atomic increment, 429 vs drop.

Trap

In-memory limits per instance (3 boxes = 3× the budget behind plate 35). IP-only (CGNAT shares one address; mobile IPs rotate). 429 on a charge with no idempotency key (plate 29).
