DSATop-k · Dijkstra

Always pop the next best.

A priority queue pops the smallest (or largest) currently stored, not the oldest. Under the hood: a heap. Keep k, don’t sort n (plate 63). Dijkstra pops the closest unsettled node. Merge k lists pops the smallest head (plate 161).

Min-heap of size k

Top-k

k-frequent on counts size k, root = weakest if x.count > root: replace root

O(n log k). You did not sort n. k-largest is a min-heap of k.

Next closest node

Dijkstra

(dist, node) pop smallest dist relax edges, push often push duplicates

Binary heap has no cheap decrease-key — find is O(n). Push again, skip stale pops.

Next deadline

Schedule

heap of (end, id) pop the task that must finish next meeting rooms II

Min-heap of end times (plate 159). Median stream uses two heaps (plate 164).

Peek is O(1). Push/pop O(log n). Change-priority is not a standard binary-heap op.

What

Abstract: insert + extract-min. Concrete: binary heap (plate 114). Fibonacci heap is theory. If you need decrease-key often, say so — then you are not in the default Java PriorityQueue.

Why

Any “next best” loop: top-k, Dijkstra, merge k lists, meeting rooms. Interviews: name the comparator out loud so they know you didn’t flip min/max.

Trap

Sorting on every insert — O(n) insert. Using a PQ for FIFO (that’s a queue). Forgetting Java PriorityQueue is a min-heap; max needs a comparator or negatives. Same flip as plate 63.
