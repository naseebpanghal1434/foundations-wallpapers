Backendpthread_mutex_t · std::mutex

A mutex is a bathroom key.

A mutex is mutual exclusion around a critical section: at most one thread holds it. POSIX: pthread_mutex_lock / pthread_mutex_unlock. C++: std::mutex + std::lock_guard (RAII unlocks). Java: synchronized / ReentrantLock. Linux waits with futex(2). Hold it only for the bytes that must not interleave — not across HTTP.

Don’t

mu.lock() if err: return // never unlock cache_mu.lock() http.Get(...) // lock × RTT

Forgotten unlock: every waiter blocks forever. One lock around the whole map: correct, and single-threaded.

What

A mutex serializes plate 73’s window. Not a condition variable (that waits for a predicate). Reentrant locks let the same thread nest; you don’t need one until you do. RW locks allow concurrent readers.

Why

Shared mutable state needs a referee. Interviews: smallest section, lock ordering, RAII, deadlock as a wait-for cycle. Fine-grained locks buy throughput and deadlock risk.

Trap

One coarse lock for the entire cache. Unlock skipped on the error path. Locking, then calling Stripe while you still hold it — every other thread waits on the network.
