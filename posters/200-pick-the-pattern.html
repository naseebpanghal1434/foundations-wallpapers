DSAInterview playbook

Name the pattern before you type.

A screen is not “have I seen this ID.” It is: sorted? window? graph? tree? DP state? Name it, then write. This plate is the map of 101–199. If you cannot name the pattern in one sentence, you are not ready to type. Complexity follows the pattern, not the other way around.

Sorted · contiguous · range

Array

Two pointers. Prefix sums. Sliding window. Monotonic stack / deque. Binary search the answer. n log n is sort or the search, not two nested fors.

Nodes, edges, reach

Graph

BFS unweighted shortest. Dijkstra if weights ≥ 0. Topo on a DAG. DSU for components / “same as.” Grid flood is a graph with 4 neighbors.

Kids, levels, bounds

Tree

Recurse both kids (LCA, diameter, path sum). BFS levels (order, right side). BST: walk with bounds, not “check the children.”

State, or choice + undo

DP

Name the state, the transition, the base, the order. List-all is backtrack (choose, recurse, pop). Count / opt is DP. Not both unless they ask.

Brute n² / n! first as a sentence so the better pattern has a baseline. Playbook: restated constraint → structure → pattern → complexity → code → the trap.

What

Playbook, not a new algorithm. Restate the constraint, pick the structure, name the pattern, quote the complexity, then type. Draw six boxes. Speak the invariant out loud. Plates 101–199 are the pieces; this is the index.

Why

SDE-1/2 interviews grade the map more than the last index bug. If you cannot name the pattern in one sentence, the code will wander. Complexity is a consequence of the pattern you picked, not a number you tack on after.

Trap

Jumping to code. DP on a graph shortest-path with nonnegative weights (that’s Dijkstra). Sliding window on non-monotonic / non-contiguous. Sorting when indices matter. Recursion on 10⁵ without a stack / iterative write.
