DSAContiguous · O(1) get

Index is address plus i.

An array is one block. Slot i lives at base + i × size — O(1), no hop. Append at the end is O(1) if capacity remains. Insert or delete in the middle shifts the tail — O(n). Binary search, two pointers, prefix sums all assume this layout.

One block · arithmetic

Index

[ 7 | 2 | 9 | 4 ] 0 1 2 3 a[2] → addr + 2×4 → 9 O(1) insert at 1 O(n) shift push at end O(1) if cap

Ints of 4 bytes. The next index is the next cache line. 2D row-major: a[r][c] is a[r*cols+c].

e.g.

Rotate right by k=2

In-place

[1 2 3 4 5] k=2 rev all 5 4 3 2 1 rev [0,k) 4 5 3 2 1 rev [k,n) 4 5 1 2 3

Three reverses, O(n) time, O(1) extra space. Same block, mutated. k %= n first.

What

Fixed-size or dynamic contiguous slots of one type. Get/set O(1). Scan O(n). Cache-friendly because the next index is the next cache line. 2D row-major: a[r][c] is a[r*cols+c].

Why

Default structure in screens. Rotate array, move zeroes, Dutch flag, prefix sums — they mutate the block. Say index, length, in-place vs extra array.

Trap

a[n] is out of bounds — last index is n-1. “Insert is O(1)” — only at the end, and only with spare capacity. Treating a Python list as a linked list: it is a dynamic array (plate 102).
