FrontendCritical rendering path

How a page paints.

The browser does not “show HTML.” It builds trees, then figures out geometry, then paints pixels. CSS and JS in the <head> can hold up first paint. Layout is the expensive geometry pass (reflow). Paint is coloring. Composite is layers on the GPU.

1

Parse

HTML → DOM. CSS → CSSOM. JS can block parsing.

2

Render tree

Visible nodes only. display:none is out.

3

Layout

Reflow. Size and position of every box.

4

Paint

Fill pixels: text, colors, shadows, images.

5

Composite

Layers to the screen. transform can skip layout.

What

DOM + CSSOM → render tree → layout → paint → composite. Changing width/height/font forces layout. Changing transform/opacity can stay on the compositor.

Why

Slow first paint is usually blocking CSS/JS or a huge HTML. Jank on scroll is usually layout in a loop (reading offsetHeight after writing styles).

Trap

Animating top/left/width (layout every frame). Or measuring in a loop: write, read, write, read — forced reflow. Prefer transform. Put defer on scripts; CSS still blocks paint.
