DSABucket or quickselect

Count. Then a heap of size k.

Top k frequent: count with a hashmap, then pick the k largest counts. Min-heap of size k — evict the smallest count — is O(n log k). Bucket sort by frequency: n+1 buckets, walk from n down, O(n). Quickselect on unique keys by count: average O(n). Sorting all uniques is O(u log u).

Default sentence

Min-heap k

[1,1,1,2,2,3] k=2 1:3 2:2 3:1 min-heap (count, key) (3,1) (2,2) size 2 (1,3) evict min pop (1,3) → key 3 keep keys 1, 2

Root is the smallest winner. Size k, not n. O(n log k) after the count.

Freq ≤ n · linear

Buckets

idx = count [3] → [1] [2] → [2] [1] → [3] walk n .. 1 take until k

n+1 buckets. O(n). Same bones as counting sort (plate 64).

Paid for everyone

Sort n

sort the array O(n log n) k=1 still n log n max-heap of n then pop k extra log n

Correct, wasteful. Quickselect on uniques: average O(n) (plate 163).

If k==n return everything. Ties: the usual spec is any k, not a stable ranking.

What

Count first — O(n), hashmap of value → freq. The second structure is the interview choice. Heap of size k is the default sentence. Buckets if you want worst-case linear. You are ranking uniques by count, not sorting the raw stream.

Why

LeetCode 347 (cousin of 215). Word frequencies, top-k URLs, heavy hitters. Plate 63 was the heap slogan; this is the full pattern: count, then select. Say min-heap, size k, evict smallest count.

Trap

Sorting the entire array O(n log n) when k=1. A max-heap of n, then pop k. A heap of size k that is a max-heap — that keeps the rare ones and evicts a winner. Skipping the count pass and heapifying raw values.
