DSAk hashes · bit array

Maybe. Never a false no.

A Bloom filter is a bit array plus k hash functions. Insert: set those k bits. Query: if any bit is 0, the item is definitely absent. If all are 1, it might be present — or those bits were set by others. False positives. No false negatives. You cannot delete (without counting).

bits 0 … 15 set 2, 7, 11 query ada 2,7,11 all 1 → maybe query kai bit 4 is 0 → no

A 0 is a hard no. All 1s is a maybe. No original keys are stored.

Density

many inserts later most bits are 1 everything looks like a maybe k ≈ (m/n) ln 2 target false-positive rate picks m and k

Clearing a bit to “delete” wipes other keys that shared it. Counting Bloom / Cuckoo if you must delete.

What

Probabilistic set membership. O(k) time, tiny memory. No original keys stored. Cannot list items. False positives yes; false negatives no. Contrast a hash set: exact, stores keys.

Why

Caches (“is this URL even in the SSD set?”), DB to skip disk, spell-check, network. System + DSA crossover. A cheap no is worth a maybe that you then check for real.

Trap

Treating maybe as yes. Deleting by clearing bits — you wipe other keys. Hashing poorly (k bits from one hash split badly). Using Bloom where a miss must be exact (auth, money).
