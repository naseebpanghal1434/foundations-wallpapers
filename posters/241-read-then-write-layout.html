FrontendReflow · thrash

Read layout. Then write. Not both.

offsetWidth, getBoundingClientRect, and scrollTop force layout. Interleaving those reads with style writes is layout thrash — geometry recomputed N times per frame.

Measure, mutate, repeat

Thrash

for (const el of els) { const h = el.offsetHeight el.style.height = h+1+'px' } // N reflows

Each write dirties layout. The next read forces it again.

trap

All reads, then writes

One snapshot

const hs = els.map(e => e.offsetHeight) els.forEach((el, i) => { el.style.height = hs[i]+1+'px' })

Batch. rAF is the frame clock. Plate 25 is the pipeline.

What

Layout is a snapshot. Writes invalidate it. One snapshot per frame if you can. transform/opacity skip layout (composite only).

Why

60fps is 16ms. One forced reflow on a big DOM can eat the frame. Jank interviews start here.

Trap

Reading layout inside a resize observer that then writes, that then reads. Animating top/left instead of transform. console.log(el.offsetHeight) in a hot path.
