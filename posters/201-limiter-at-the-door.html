Put the limiter at the door.

A rate limiter is one shared counter per subject per window: Redis INCR + EXPIRE (TTL) so every replica sees the same budget. Token bucket: tokens = min(burst, tokens + rate·Δt). Over limit: 429 with Retry-After.

Lua: INCR and the check are one round-trip. Hot user is a hot Redis key. 429 is the contract (plate 34).

What

One Redis key per IP / user / API key per window, at the gateway so the app never sees rejected traffic. Token bucket allows burst; fixed window is 1 op and spikes at :00.

Why

SDE-2 “design a rate limiter”: where it lives, the key, atomic increment, 429 vs drop. In-memory limiters lie under load-balanced replicas.

Trap

Per-process counters. Fixed window 100/min: 100 at 12:00.99 + 100 at 12:01.00. No Retry-After. Limiting /login and leaving /signup open.
