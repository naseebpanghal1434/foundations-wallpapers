Gen AIJSON schema · think→call→observe

Tools are functions the model calls.

The model cannot query your DB. It can emit a tool call that matches a JSON schema you sent: get_order({ "id": 88 }). Your process runs it (with authz), returns JSON, the model writes prose. The model proposes; you execute. Sample the call at T=0 (plate 44).

1

You send tools + questionJSON Schema: name, parameters, types. “What’s the status of 88?” Parallel calls possible.

2

Model returns a call, not proseget_order({id: 88}) — you parse, you authorize (plate 14), you run. Cap steps (e.g. 8).

3

Feed the result backrole=tool {status:"shipped"} → “Order 88 shipped.” Repeat if more tools. Timeouts, 429, idempotency still yours.

observe
What

Function calling / tools / agents: think → call → observe. You own side effects, timeouts (plate 19), idempotency (plate 29), injection (plate 46). Keep the allowlist tiny. The model never holds the DB credential.

Why

How “chat with your data” is supposed to work — not by stuffing the table into the prompt. Interviews: draw the loop, say who executes.

Trap

Letting the model pick arbitrary SQL. Trusting args without authz (IDOR on id: 88). No max steps (infinite loop). Showing raw tool errors. Secrets in tool descriptions.
