BackendContent-Security-Policy · nonce

CSP lists who may run script.

Content-Security-Policy is a response header: script-src 'self' https://cdn.example 'nonce-abc' — inline script without that nonce does not run, even if XSS injected it (plate 234). Other directives: default-src, img-src, connect-src, frame-ancestors. Start with Report-Only to measure.

1

Header: script-src 'nonce-R4nd'Per-request random nonce. Hashes ('sha256-…') for static inline. default-src is the fallback.

CSP
2

<script nonce=R4nd src=/app.js>Same nonce as the header. Browser allows this element. CDN host must be in script-src too.

allow
3

Injected <script>alert(1)</script> blockedNo nonce, not 'self', not a listed host. 'unsafe-inline' disables this win.

block
What

An allowlist the browser enforces. Defense in depth, not a sanitizer replacement (plate 234 still applies).

Why

XSS residual. Clickjacking via frame-ancestors. Data exfil via connect-src.

Trap

'unsafe-inline' and 'unsafe-eval' in production. A nonce that is static. CSP only on the homepage.
