BackendSOP · https://a:443

Origin is scheme, host, and port.

Same-origin policy: two pages share an origin iff scheme, host, and port all match. https://app.com ≠ http://app.com ≠ https://app.com:4443 ≠ https://api.app.com. Cookies use site (eTLD+1, plate 233), which is coarser; CORS (plate 15) is the browser asking the other origin for permission.

scheme + host + port

Same origin

https://a.com/x https://a.com/y https://a.com:443/z https ≡ port 443 http ≡ port 80

Path and query are not in the origin. DOM, localStorage, and JS reads share this unit.

vs

one field differs

Different

http://a.com scheme https://a.com:4443 port https://api.a.com host api.a.com is same-site file:// is opaque; iframe sandbox → null

Same-site (eTLD+1) is not same-origin. Subdomains do not share origin.

What

The browser’s isolation unit for DOM, storage, and the cousin rules around cookies. Triple: scheme, host, port — nothing else.

Why

XSS is same-origin execution (plate 234). Fetch to another origin is CORS (plate 15), not a firewall.

Trap

Thinking subdomains share origin. document.domain hacks. Comparing origin to hostname only, or treating https://a.com and https://a.com:4443 as one.
