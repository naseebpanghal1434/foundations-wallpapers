Langtype feedback · deopt

JIT compiles the hot path and may undo it.

V8/HotSpot: count calls, record types (this + is always Smi / HiddenClass H). When hot, compile a specialized native version. If a new type appears, deoptimize back to interpreter/baseline and maybe recompile. That’s why warmup exists and why megamorphic call sites stay slow.

1

InterpretV8 Ignition / HotSpot interp. Collect type feedback in inline caches. First request is this path.

cold
2

~10k hits, types stableSmi, one HiddenClass / shape. CHA in Java: the receiver has one impl. Ready to specialize.

feedback
3

NativeTurboFan / C2 emit machine code for that shape. Inlined, unboxed, no tag dance (plate 329).

hot
4

Unexpected class → deoptNew map, a double where a Smi lived, a fifth implementation. Back to baseline; megamorphic stays slow.

undo
What

Speculative native code. Correctness via deopt, not via remaining generic. Polymorphism (many shapes, many impls) kills the speculation (plate 323).

Why

Why the first request is slow. Why a megamorphic interface in a hot Java loop loses inlining. Why a 30 s JVM bench exists.

Trap

Benchmarking without warmup. Changing shapes every iteration (obj[k] = i with random keys). Passing many unexpected types “just in case” through a hot function.
