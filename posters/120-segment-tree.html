DSARange query · point update

Each node is a range.

A segment tree is a binary tree over the array’s ranges. The root is [0,n). Left is the first half, right the second. A node stores an aggregate (sum, min, gcd) of its range. Query and point update walk O(log n) nodes. Build is O(n).

a = [1, 3, 5, 7] · sum

The tree

16 [0,4) / \ 4 [0,2) 12 [2,4) / \ / \ 1 3 5 7 query [1,3) = 3+5 full leaf + full leaf

Invariant: node = merge(left, right). Tree array size ~4n. Half-open [l,r).

vs

Point update, walk up

Set a[2]=10

leaf 5 → 10 [2,4) 12 → 17 root 16 → 21 [1, 3, 10, 7] walk to the leaf, set, recompute each parent

O(log n) nodes touch. Fenwick does prefix sums simpler (plate 121). Min/gcd want this tree.

What

Associative merge (sum, min, max, gcd). Point update + range query, or lazy range update. Index-tree form or recursive with mid. ~4n slots so 2*node / 2*node+1 never run off the end.

Why

Range-sum / range-min with updates. Interview bar: say the invariant “node = merge(left, right)” and O(log n). Prefix arrays die the moment one cell changes.

Trap

Building n². Off-by-one on half-open [l,r). Using a segment tree when a prefix array would do (no updates). Lazy propagation without a spec for range add — skip unless asked.
