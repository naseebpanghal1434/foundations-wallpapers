BackendQueue · delay · at-least-once

A job is a message with a clock.

Work that is not the HTTP response is a job: enqueue (SQS / Redis streams / Kafka), visible_at for delay, worker leases, acks. Visibility timeout must exceed runtime — 30 s timeout on a 2 min transcode is two workers. At-least-once (plate 92) → idempotent handler (plate 225). Poison → DLQ.

DLQ
What

Async boundary + lease + ack + DLQ. Delay is visible_at, not sleep in the API. “Exactly once” without an idempotency key is a slogan.

Why

Almost every SDE-2 design has a worker. They want: why not in-request, retries, poison messages, idempotency.

Trap

sleep(10 minutes) in a web worker. No DLQ so poison blocks the queue. Visibility timeout 30 s on a 2-minute transcode. “Exactly once” with no key.
