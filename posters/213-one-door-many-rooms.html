SystemAPI gateway · BFF

One door. Many rooms.

An API gateway is the shared edge: TLS (plate 78), JWT, rate limit (plate 201) with Redis INCR+TTL, route /v1/users → users, X-Request-Id. A BFF is a per-client gateway (mobile JSON ≠ web). AuthN here; authZ in the service that owns the row (plate 14).

Edge in every box

Drift

users: JWT, CORS, 429 pay: JWT, CORS, 429 chat: JWT… different clock no shared request id timeouts? maybe limiter in RAM

Forty copies of CORS. One service forgets the limiter. AuthZ copy-paste is still wrong.

vs

Cross-cutting at the edge

Gateway

Client → gateway TLS, JWT, 429 Retry-After /v1/users → users /v1/pay → payments BFF = per-client shape timeouts, breakers

The gateway is not the monolith and does not own SQL. GraphQL can be a BFF. Breakers: plates 19, 39. Default timeout 1–3 s.

What

TLS, authN, 429, routing, request-id at the edge. AuthZ stays in the service that owns the data. One id through the logs (plate 84).

Why

Microservices design. They want one shared edge, not 40 copies of CORS. Contrast: the gateway does not own SQL.

Trap

Business rules in the gateway until it is the monolith. Gateway as the only authZ. No timeout so a sick payment service holds every mobile request.
