FrontendIf-None-Match · 304

ETag asks: has this changed?

ETag is a version token for a representation. The client sends If-None-Match; a match returns 304 Not Modified — no body, the cache already has the bytes.

1

First GET keeps a tokenGET /app.js → 200 plus ETag: "abc". Pair with Cache-Control: no-cache so it stores but revalidates.

304 — empty body, same bytesSuccess with no payload. The cache already has the file. Must-revalidate on money pages.

304
What

Validator + conditional GET. 304 is success with an empty body. The cache already has the bytes.

Why

Fast reloads, CDNs, APIs with big JSON. Cheaper than max-age when content changes often.

Trap

New ETag every response (timestamp) — 304 never hits. Gzip changing ETag vs identity. Ignoring 304 and parsing an empty body as JSON.
