BFS is a queue. DFS is a stack.

BFS: push neighbors on a queue, pop the oldest. You finish a level before the next — first time you hit a node is the fewest edges. DFS: a stack, or recursion’s call stack; go deep, then backtrack. Same graph (plate 60). Different order. Only BFS is unweighted shortest path.

FIFO · level by level

BFS

q: [A] [B C] pop A [C D E] pop B first time we see D: dist[D] = dist[B] + 1 = 2 ← shortest in edges
Unweighted shortest. Grid: rotten oranges, word ladder.
Mark visited when you enqueue, not when you pop.
vs

LIFO · go deep

DFS

stack / recursion A → B → D → … first path to D may be 5 edges not shortest cycle A—B, no visited: A → B → A → B → …
Cycle, connected components, topo (finish times), a maze.
Recursion depth = path length. Stack overflow is a real bug.
What

Queue vs stack is the whole trick. Both O(V+E) with a visited set. Weighted shortest is Dijkstra (a heap, plate 63) or 0-1 BFS — not “DFS with a depth variable.”

Why

“Shortest path in a maze / bus stops / friendship hops” is BFS until someone says weights. Interviews fail people who DFS and return the first path they find.

Trap

DFS for shortest path. No visited on a graph with cycles (infinite, or exponential re-walks). Marking too late in BFS so the same node sits in the queue ten times. Directed vs undirected: still visit once; undirected without visited is an instant bounce.
