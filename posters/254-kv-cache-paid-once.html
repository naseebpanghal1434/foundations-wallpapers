GenAIAttention · prefix

KV cache is the past, paid once.

Attention needs keys and values of every previous token; the KV cache memos them so you do not recompute the prefix. Prefill builds the cache; decode appends one token — first token slow, the rest cheaper (plate 266).

for each new token: re-attend all n n² waste

Re-embedding the whole prompt on every decode step. That is not how serving works.

vs

Prefill once, then decode

Memo

prefill → KV decode: 1 vs n append, reuse

Cache size ≈ layers × n_tokens × d × 2. Long chats eat GPU RAM, not just the window.

What

Memoized attention state. Prefix reuse across requests is prompt caching (plate 265).

Why

Streaming, chat, and why batching decode is a different game from prefill.

Trap

A system-prompt change at token 0 invalidates the whole cache. The cache is math, not a diary the model “understands” (plate 12).
