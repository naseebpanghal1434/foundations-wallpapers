DSAO(1) · log n · n · n²

Big O is the growth, not the stopwatch.

Big O says how cost grows as n grows — not how many milliseconds this laptop took. Drop constants and slower terms. Interviews want the class, and which loop made it that way.

Constant

O(1)

Array index. Hash get. Same work at n=10 and n=10⁷. (Average — plate 51.)

Halve each step

O(log n)

Binary search. Balanced tree. 2³⁰ ≈ 1e9; thirty steps, not a billion.

Touch each once

O(n)

Scan, two pointers, sliding window. Linear in the input. The honest default.

Every pair

O(n²)

Nested loops over n. 10⁴ × 10⁴ = 10⁸ ops — the usual timeout in a screen.

What

An upper bound on growth. “Does not grow faster than f.” Θ is tight; interviews accept O. Space uses the same classes. O(n log n) is sort / divide-and-conquer, not two fors.

Why

n = 10⁶: O(n) is fine, O(n²) is dead. n = 10⁹: even O(n) may be tight. Pick the structure before you type. A stopwatch on n=10 tells you nothing about n=10⁷.

Trap

Nested for i / for j claimed as n log n because “log feels nested.” That is n². Calling an O(n) helper inside a loop and reporting O(n). “Hashmap is O(1)” as a law (plate 51).
