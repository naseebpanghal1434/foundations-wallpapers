SystemCache-Control · PoP

A CDN is a cache near the user.

A CDN is HTTP caches at points of presence. First Mumbai GET for /app.a1b2.js is a miss to origin (us-east-1, ~180 ms); the next are HIT at ~20 ms. Cache-Control: public, max-age=31536000, immutable is the contract. You buy RTT and origin offload.

edge HIT

~20 ms

PoP nearby. CF-Cache-Status: HIT. Age: 412. Origin never sees the request.

origin MISS

~180 ms

Ocean RTT + origin TTFB. Then the PoP stores the object. Hit ratio is the metric.

hashed asset

1 y

max-age=31536000, immutable. Filename is the version: app.a1b2.js. Purge is a fallback.

HTML / API

60 s

Short TTL or s-maxage. Cache-Control: private on /api/me. Vary: Cookie is often “don’t cache.”

What

PoP = point of presence. Headers: Cache-Control, s-maxage, ETag, Age. HTML often 60s; fingerprinted JS/CSS a year. Purge / versioned URLs when you ship a new bundle.

Why

~2e8 m/s in fiber; an ocean is ~100–200 ms. Interviews: “make a global site fast” starts here, then cache (plate 08), then SSG (plate 28).

Trap

Caching HTML that contains the user (personalization needs a cache key, or don’t). Caching /api/me. No hash in the filename + long TTL = users stuck on old JS until you purge every PoP.
