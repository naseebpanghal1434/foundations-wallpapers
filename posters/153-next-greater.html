DSAMonotonic stack

A decreasing stack remembers who waits.

Next greater element: for each i, the first j > i with a[j] > a[i] (or -1). Nested scan is O(n²). Monotonic decreasing stack of indices: walk left to right; while the top is smaller than a[i], it just found its next greater (i). Push i. What remains has no greater to the right.

Each index push/pop once

Walk L → R

[2, 1, 2, 4, 3] i=3 (4) pops 2,1,2 their next is 4 stack then [4, 3] ans [4, 2, 4, -1, -1]

Stack holds a decreasing sequence of candidates still waiting. O(n) because each index enters and leaves once.

Circular / smaller

circular (LC 503): walk the array twice idx = i % n still one stack next smaller: increasing stack histogram is that (plate 154)

Daily temperatures = next warmer day. 2n−1 looks, not an infinite loop. Fill ans[i] at most once.

What

Store indices, not values — you need ans[i]. Decreasing stack for next greater; increasing for next smaller. The invariant is “whoever is still on the stack has not seen a better bound yet.”

Why

LeetCode 496 / 503 / 739. Histogram (plate 154) and rain-water stack variants sit on this. Say “monotonic stack” in the first sentence.

Trap

Comparing values vs indices. Walking right-to-left for next-greater-to-the-right without flipping the meaning. Using a queue. Forgetting circular needs 2n−1 looks, not infinite. Nested j-loop — you paid n².
