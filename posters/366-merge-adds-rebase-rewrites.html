Toolsfast-forward · --force

merge adds a node. rebase rewrites hashes.

Merge C onto M: if M is an ancestor, fast-forward (move the name); else a new commit with two parents. Rebase C onto M: replay C’s unique commits as new objects with new hashes on M. Shared published hashes should not be rebased without coordination.

DAG append

merge

M -- m2 -- M' \ / C1 --- C2 M' parents: m2 and C2 C1, C2 hashes stay history shows the join

Fast-forward is just moving the name. No new object if already ancestor.

vs

New objects · old orphaned

rebase

M -- m2 -- C1' -- C2' C1, C2 still in reflog ~30 days, then GC linear; hashes changed force-with-lease, not --force

Conflicts are the same content problem. The DAG edit is the difference.

What

Merge appends a node (or slides a name). Rebase copies commits; new parent → new hash (plate 364).

Why

Branch policy. Why a force-push breaks other clones that still hold the old C hashes.

Trap

Rebasing main onto a feature (inverted). Rebase after someone pulled your branch. merge --no-ff spam vs always-rebase fights.
