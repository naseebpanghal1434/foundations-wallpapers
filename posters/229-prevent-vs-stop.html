FrontendDefault action · travel

preventDefault is not stopPropagation.

preventDefault cancels the UA action (navigate, submit, type). stopPropagation stops travel to other nodes — they are independent, so you can cancel a link and still bubble, or stop travel and still submit.

cancel the UA, still travel

preventDefault

a.addEventListener('click', e => { e.preventDefault() }) // no navigation // parent still hears the click

Default = the browser’s built-in. Parent listeners still run (plate 228).

not

stop travel, default may fire

stopPropagation

btn.addEventListener('click', e => { e.stopPropagation() }) // form listener never runs // submit default might still fire

return false in old onclick does both. In addEventListener it does neither unless you call them.

What

Default = the UA behavior. Propagation = other listeners. stopImmediatePropagation also blocks later listeners on the same node.

Why

Forms, links, drag, contenteditable. Interviews mix the two names on purpose.

Trap

stopPropagation to “cancel the link.” Using return false in an addEventListener handler. React: e.preventDefault() on a div thinking it stops a nested button.
