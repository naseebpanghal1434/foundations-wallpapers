Comments are a tree, served as a page.

Comments are parent_id trees under a post. Do not SELECT 40k nodes for a viral thread. Serve a page: 20 roots by (score, id) + 3 replies; “12 more” is a cursor. Soft-delete → [deleted], children stay. Adjacency insert is O(1); materialized path makes descendants cheap.

Viral post · 40k nodes

Whole tree

WITH RECURSIVE t AS ( SELECT * FROM comments WHERE post_id = 7 UNION ALL ... ) -- 6 levels, 40k rows first paint: all of them

Fine when the thread is small. Recursing the forest on the request is not a page. Hard-delete orphans children.

vs

Page, then a slice

20 + 3

20 roots ORDER BY score, id cursor = (score,id) first 3 replies each '12 more' is a cursor deleted → '[deleted]' children stay cache page 1

Votes are a counter with a rate limit (plate 201). Live new comments: socket on post id (plate 216).

What

Tree in storage, page in the API. Cursors, not OFFSET (plate 32). Moderation is a state, not DELETE … CASCADE. Hot post: cache the first page.

Why

Reddit / HN design. They want nesting + pagination + [deleted] — not a CASCADE wipe of the thread.

Trap

Loading 40k comments on first paint. Deep recursion in the API. Hard-delete that breaks the tree. Ranking every nested reply globally so a new child of an old thread never surfaces.
