DSAPush O(1) · getMin O(1)

Store the min with the value.

Min stack: push, pop, top, getMin all O(1). Each node (or a parallel stack) stores the min of everything at or below it. Push x with new_min = min(x, current_min); pop one pair. A second stack that only pushes when x ≤ current min also works — and saves space on increasing sequences.

Each depth carries its min

Pairs

push -2 (-2, min=-2) push 0 ( 0, min=-2) push -3 (-3, min=-3) getMin -3 pop getMin -2 still there

You never scan. Same bones: a max stack. Queue-min is a monotonic deque (plate 136).

or

Push a min only on ≤

Two stacks

vals: -2, 0, -3 mins: -2, -3 pop: if x == mins.top: mins.pop() push: if x <= mins.top mins.push(x)

≤ not < — two copies of the min each get a slot, so a pop cannot lose the other.

What

Auxiliary min at each depth. The live min is always the top of that channel. One variable is not enough: a pop has to restore the previous min without a scan.

Why

LeetCode 155. Tests that O(1) min cannot be “look at every item.” Interview follow-up: max, or min in a queue (deque, not this).

Trap

Scanning the stack on getMin. Using < so two copies of the min, pop one, min is gone. Updating a single min variable on pop without knowing what the previous min was.
