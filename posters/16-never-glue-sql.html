Database$1 · PQexecParams

Never glue SQL with strings.

SQL injection is concatenating untrusted bytes into the query string so the parser treats them as syntax. Parameterized queries send a prepared statement plus bind values ($1, ?, PQexecParams). The value is data. It is never compiled.

id = 1 OR 1=1

Glued

query( "SELECT * FROM users WHERE id = " + req.query.id ) → WHERE id = 1 OR 1=1 -- every row -- ORDER BY ${col} is syntax too -- identifiers cannot be bound

The input became syntax. Escaping quotes by hand misses encodings. OWASP injection class.

vs

Same bytes · bound

$1

query( "SELECT * FROM users WHERE id = $1", [req.query.id] ) command: WHERE id = $1 value: "1 OR 1=1" int parse fails → 0 rows text stays a string

JDBC PreparedStatement, psycopg2, Prisma tagged sql. .raw() / $queryRawUnsafe opt out.

What

Placeholders keep structure and values apart at the protocol. ORMs do this until you build a string.

Why

One missed endpoint dumps users. Interviews: bind values; whitelist identifiers.

Trap

IN (${ids.join(',')}) is still glue — use = ANY($1). ORDER BY ${col} cannot be bound; whitelist. LIKE '%' + q + '%' with concat is injection plus a leading-wildcard seq scan.
