OSTASK_UNINTERRUPTIBLE · EAGAIN

Blocking I/O sleeps the thread.

read() on an empty socket: the thread leaves the runqueue (sleeps) until data or a signal. The CPU runs someone else. O_NONBLOCK: return EAGAIN/EWOULDBLOCK instead. Async: epoll/io_uring so one thread waits on many fds (plate 300).

One thread per connection

Blocking

200 threads × 1 conn each sleeps in read stack VA × 200 simple code stuck NFS → D-state
vs

One thread, many fds

Evented

1 thread epoll_wait 10k fds EAGAIN → next fd state machine

D-state (TASK_UNINTERRUPTIBLE) ignores signals. Node/nginx = nonblocking + event loop (plate 4).

What

Sleep is the cost of simple code. Nonblocking is the cost of state machines. Neither is “faster” without the metric: connections per RAM vs latency.

Why

Thread-per-connection vs evented servers. Why a stuck NFS is D-state (uninterruptible).

Trap

Blocking in an event-loop thread (janks everyone). 10k threads as a “simple” C10k solution.
