Backendapp.use · next() · 4-arity

The request walks an onion.

Express middleware is (req, res, next) => { … next() }. app.use order is outside-in: first registered runs first. Koa’s await next() is the same pipeline — code after next() runs on the way out. Skip next() and the request hangs until the client timeout. Error handlers are (err, req, res, next) — four arguments, last.

What

Cross-cutting lives here — auth (plate 14), CORS (plate 15), rate limits (plate 33), body parser — not copied into every route. First app.use is outermost.

Why

One place to reject, time, and parse. Interviews: draw the pipeline, say when your code runs (before vs after the handler), and what happens if you don’t call next().

Trap

auth after the route — the handler already ran unauthenticated. Forget next() → hung request, no 500. Error middleware with three args, or not last — Express never calls it.
