Toolsgit add · staging

The index is the next commit.

Three trees: HEAD (last commit), the index/staging (what commit will write), and the working directory. git add copies worktree → index; git commit writes a tree from the index and a commit whose parent is HEAD. git reset moves those pointers; the flags decide how far.

Edit, never add

Worktree

HEAD README = v1 index README = v1 worktree README = v2 commit → still v1 status: modified, unstaged

The next commit is the index, not the files on disk.

vs

Add, then edit again

Staged

add → index = v2 edit → worktree = v3 commit writes v2 v3 stays unstaged restore --staged un-copies index ← HEAD

git status is the three-way diff of HEAD / index / worktree.

What

A snapshot you build, then name. Not a list of patches. add records bytes at that moment.

Why

Partial commits. “Why didn’t my change ship” — it was in the worktree, never the index.

Trap

commit -a as a reflex: skips new untracked files, includes every tracked edit. Assuming add watches the file afterward.
