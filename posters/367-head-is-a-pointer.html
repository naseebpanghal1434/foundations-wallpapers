Toolsrefs/heads · detached

HEAD is a pointer. A branch is a name.

refs/heads/main is a file holding a commit hash. HEAD is usually a symbolic ref to that name. Detached HEAD means HEAD is a raw hash — new commits are reachable only via that hash or the reflog until you name them; tags don’t move unless -f.

HEAD → refs/heads/main → 9c3.git/HEAD contains ref: refs/heads/main. A commit updates the name, not HEAD’s text.

checkout 9c3^ — detachedHEAD now stores 40 hex chars. Commits you make hang off that hash only.

branch save — now a namegit switch -c save writes refs/heads/save. origin/main is a remote-tracking name.

label

Deleting a branch deletes the name, not the objects — GC later if nothing else points at them. Fetch updates origin/*; checkout does not.

What

Names are cheap, movable labels on the object DAG. HEAD is which name (or hash) you are on.

Why

“Where did my commit go?” — detached. Why deleting a branch does not delete objects immediately.

Trap

Committing for an hour detached, then checkout main. Thinking origin/main updates without fetch.
