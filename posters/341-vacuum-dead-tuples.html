Databasexmin xmax · bloat

VACUUM marks dead tuples reusable.

MVCC (plate 96): UPDATE/DELETE insert a new version; the old stays until no snapshot can see it. VACUUM (and autovacuum) freeze and mark those ItemIds free. It does not shrink the file unless VACUUM FULL (a rewrite). Bloat is dead tuples occupying 8 KiB pages.

Ordinary VACUUM recycles space inside the file. The OS does not get the bytes back.

HOT may vacuum a page in place (plate 350). Freeze is wraparound (plate 342), not optional.

What

Garbage collection for tuples. Dead = xmax committed and no snapshot still needs xmin. Space is reused; the relation size is a high-water mark.

Why

Table growth after batch updates. A long idle in transaction pins xmin and blocks vacuum — that is the bloat incident.

Trap

Turning autovacuum off. VACUUM FULL on a hot table (exclusive lock). Expecting VACUUM to always release bytes to the OS.
