DSATop k

Keep k. Don't sort n.

A heap is a priority queue: insert and extract-min in O(log n), peek min in O(1). The interview move is k-largest: a min-heap of size k. Walk n items; if x is bigger than the current min of the large ones, replace. O(n log k). You did not sort the array.

Whole array · then slice

Full sort

[3, 1, 5, 12, 2, 11] k=3 sort → [1, 2, 3, 5, 11, 12] take last 3 O(n log n) you paid for 1 and 2

Correct. Wasteful when k ≪ n. Same trap as sorting to find a min (that’s a scan).

vs

Min-heap of size k

Heap of k

k-largest, min-heap: [3] → [1,3] → [1,3,5] 12 > 1 → [3,5,12] 2 skip 11 > 3 → [5,11,12] O(n log k) space O(k)

Root is the smallest of the winners. k-smallest: max-heap of k. Java PriorityQueue, Python heapq — both min-heaps.

What

Binary heap = complete tree in an array (plate 58). Heapify the whole array in O(n), then k extracts is O(n + k log n) — use that when k is large. Only need the kth, not the k sorted? Quickselect, average O(n).

Why

Streams, “top 10,” merge k sorted lists (heap of k heads), Dijkstra / Prim (the next-cheapest edge). Interviews: say min-heap for k-largest out loud so they know you didn’t flip it.

Trap

Full sort instead of a heap of k. A max-heap of size k for k-largest (that keeps the small ones). Using a heap as a search tree (plate 58). Forgetting that heapq is min-only — largest means push -x or invert the comparator.
