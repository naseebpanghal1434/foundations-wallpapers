SystemL4 TCP · L7 HTTP

A load balancer is a door.

Clients dial one VIP. The load balancer picks a healthy backend. L4 (OSI transport): TCP/UDP 5-tuple, no HTTP. L7 (application): Host, path, header, cookie. Health check: GET /healthz → 200, else remove the node.

Layer 4 · transport

L4

5-tuple src 203.0.113.4:49152 dst 10.0.0.8:443 TCP → instance B NLB, IPVS, HAProxy tcp no /api vs /static

Fast, cheap, connection-level. TLS may terminate later. No path routing.

vs

Layer 7 · application

L7

GET /api/me Host: api.shop.io → app pool GET /static/app.js → CDN ALB, Envoy, nginx http TLS terminate, drain idle timeout e.g. 60s

Sees the request. Routes, rewrites, sticky cookie. More CPU per request.

What

Algorithms: round-robin, least-conn, consistent hash (plate 91). Fail 3 health checks / 5s → out. Drain: no new conns, wait in-flight, then SIGTERM. Idle timeout on the LB must exceed the app’s.

Why

Without a VIP, users bookmark one box, and that box is the outage. With one, you add copies and survive a crash — if the app is stateless (session in Redis, not RAM).

Trap

Sticky sessions so you can keep sessions in RAM — the balancer covering an app bug. Health check hits / (slow, login wall, false-healthy). No backend timeout (LB hangs with the app). L4 expected to route by URL.
