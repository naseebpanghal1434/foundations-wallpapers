Backend12-factor · process.env

Secrets do not live in git.

Twelve-factor: the same image in every environment; config is injected at runtime. DATABASE_URL and STRIPE_SECRET come from process.env (k8s Secret, AWS Secrets Manager, Vault). A sk_live_… committed to git is leaked — .git history keeps it after git rm.

const STRIPE = "sk_live_51N…" // config.js on main .git history still has it after you git rm

Private repo is not a vault. Forks, CI logs, laptops, backups all see it. Rotate the key; rewriting history is not enough if it was pushed.

Injected at run

Env

process.env.STRIPE_SECRET process.env.DATABASE_URL .env gitignored prod: k8s secret / SM same image, different env

Build once (plate 90). Rotate a key without a new SHA. Constants (ok in git) ≠ deploys (host, keys, flags).

What

Config in the environment, not files in the artifact. Secrets: a manager — not secrets.py. Fail boot if a required var is missing; do not default to a live key.

Why

Same bits in staging and prod. Dev can run without prod keys. Interviews: “where does the Stripe key live?” — env, not the repo.

Trap

Prod keys in the repo. Committing .env. Logging process.env on boot. A config file per environment that drifts so you cannot reproduce prod.
