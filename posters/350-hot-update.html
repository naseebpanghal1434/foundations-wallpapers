DatabaseHeap Only Tuple · fillfactor

HOT updates skip the indexes if indexed cols didn't change.

If UPDATE does not change any indexed column and the 8 KiB page has free space (fillfactor 70–80 on hot tables), Postgres can chain a new tuple on the same page without touching indexes. Else every index on the table gets a new entry — bloat.

What

Page-local new version. No index insert, no index delete. Vacuum of that page can prune the chain in place.

Why

High-churn rows (counters, locks, sessions). An extra index on updated_at makes every SET a full index write.

Trap

Indexing a column you UPDATE every time (updated_at). fillfactor 100 on that table — no room, no HOT, index bloat instead.
