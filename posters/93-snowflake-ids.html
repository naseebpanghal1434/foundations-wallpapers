SystemDistributed ids

Time, worker, sequence.

You need unique ids without asking a single database sequence on every insert. A Snowflake is a 64-bit int: timestamp + worker id + per-millisecond counter. Roughly time-ordered, fits in a bigint, minted on the app box. UUID and DB sequences are the other two answers — know when each one hurts.

Random 128-bit

UUID

v4 random v7 time-ordered

No coordinator. v4 scatters B-tree inserts and is wide. v7 is the modern default if you want a UUID.

One counter

DB seq

SERIAL / IDENTITY nextval('…')

Simple, monotonic, unique. A round-trip (or a hotspot). Sequential ids leak volume and are guessable (plate 100).

64-bit, local

Snowflake

41b time 10b worker 12b seq / ms

Twitter’s layout (5+5 datacenter/worker is the same 10). k-sortable. One machine, no DB hit.

What

Mint ids where the write happens. Time makes them roughly ordered (better indexes than v4). Worker uniqueness is a config problem: each box needs a distinct id. Sequence covers bursts in the same millisecond (4096/ms/worker).

Why

Sharded writes (plate 37) cannot share one SERIAL. Interviews: three options, one cost each. “Just UUID” is acceptable if you say v7 and the width.

Trap

Clock skew: NTP steps backward, you emit an id you already emitted — generators must wait or refuse. Two pods with WORKER_ID=1 collide. Assuming ids are a total order across datacenters. Using Snowflake as a security token (still guessable-ish if worker+time leak).
