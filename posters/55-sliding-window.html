DSASubarray, linear time

Expand right. Shrink left.

A window is a contiguous slice [left, right]. Grow right to include the next item. When the constraint breaks, advance left until it holds again. Each index enters and leaves at most once — O(n). Restarting a scan at every i is how you accidentally write O(n²).

Left and right only move forward

One pass

l = 0 for r in 0..n-1: add a[r] while invalid: remove a[l]; l++ best = max(best, r-l+1)

Map/count inside the window is the constraint. Longest substring without a repeat is this.

trap

New inner scan from every i

Restart

for i in 0..n-1: seen = {} for j in i..n-1: if a[j] in seen: break seen.add(a[j]) # every i starts over # O(n²)

You threw away the work from i. Slide: drop a[i], keep the rest. Fixed-k window is the same with l = r-k+1.

What

Variable window (longest / shortest that satisfies …) or fixed (max sum of k). Subarray, not subsequence — items are adjacent. Two pointers that never go backward (plate 54’s cousin).

Why

“Longest substring / shortest subarray that …” is this pattern. Interviews want the O(n) argument: left and right each move ≤ n times, so add/remove is ≤ 2n.

Trap

Restarting an inner loop from each i (O(n²)). Shrinking past a still-valid window. Using a window for a non-contiguous subsequence. Forgetting to update the running count when left moves.
