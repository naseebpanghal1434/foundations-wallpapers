FrontendSSR · checksum

Hydration must match the HTML.

SSR sends HTML; hydration attaches React to those nodes — the first client tree must equal the server tree. Date.now(), Math.random(), locale, and typeof window in render are the usual bombs.

server HTML ≠ first client render

Mismatch

server 10:00 “Good morning” client 11:01 “Good afternoon” checksum fail DOM thrown away

if (typeof window) in render. Invalid HTML (p inside p) the browser rewrote before React saw it.

vs

stable first paint

Match, then effect

render a placeholder read time in useEffect data that differs per request: server already put it in the HTML

suppressHydrationWarning is a scalpel for the clock, not a license. Streaming SSR still hydrates islands.

What

First client render = server HTML. Effects run after hydrate. Per-request data belongs in the HTML the server already computed.

Why

Next/Remix interviews. “Why does SSR flash?” is often a hydrate mismatch or a client-only branch (plate 28).
