NetworkStreams · status codes

gRPC is protobuf on HTTP/2.

gRPC is HTTP/2 streams, protobuf payloads, and a method path. Status lives in trailers (grpc-status), not only HTTP 200 — HTTP can be 200 with an application error.

JSON REST

HTTP code

GET /orders 200 { … } 404 / 500 HTTP status is the app error

One request, one response, one code. Browsers speak this natively.

vs

POST /pkg.Svc/Method

Trailers

POST proto bytes HTTP 200 trailers: grpc-status: 0 OK or 14 UNAVAILABLE unary · stream · bidi

Deadlines are first-class. Load balancers must be h2-aware (plate 35). Field numbers are the contract (plate 83).

What

RPC on H2 with typed messages. Four modes: unary, server stream, client stream, bidi. Interceptors are middleware (plate 81).

Why

Service meshes, mobile-to-backend, internal APIs. Interviews: how it maps to HTTP. Browsers need gRPC-Web or a proxy.

Trap

Treating HTTP 200 as success. Browser talking native gRPC without a gateway. Changing proto field numbers. JSON-over-gRPC cargo cult.
