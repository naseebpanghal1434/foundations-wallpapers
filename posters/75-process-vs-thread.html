Backendfork vs clone(CLONE_VM)

Processes isolate. Threads share.

A process has its own address space (mm_struct, page tables, heap, fd table) and a PID. fork is copy-on-write, not a full copy. A thread is clone(CLONE_VM|CLONE_FILES|CLONE_SIGHAND) — pthread_create: same heap, own stack (~8 MiB), own registers. SIGSEGV kills the process, not one thread.

Process

pid 4412 fork() / posix_spawn own mm, own heap, own fds crash → this pid exits IPC: pipe, socket, mmap MAP_SHARED

Chrome: one renderer per site. A kill here does not take the parent. Two processes do not share a global.

vs

Same mm, many stacks

Thread

pid 4412 tid 7 pthread_create same heap, same fds own stack, own TLS crash → the process dies talk: just memory

Cheaper spawn, cheaper switch (plate 80). Shared HashMap is a race (plate 73). CPython GIL: threads don’t parallelize CPU.

What

Process = isolated virtual memory (plate 79) plus a PID. Thread = a scheduled stack inside that map. Heap is shared; stacks are not. Mutexes (plate 74) are how threads pretend they don’t share.

Why

Pick processes (workers, Chrome tabs, containers) when a crash must not take the house down. Pick threads when requests share a cache and you will lock it.

Trap

Threads because they’re “faster,” then racing on shared memory. Or two processes and a global variable — there isn’t one. Use a socket, a queue, or explicit MAP_SHARED.
