FrontendCall stack · task queue

The stack runs. Then the queue.

JS is one stack: a call runs to completion. When the stack is empty the loop takes a task (click, timer, I/O); render is its own turn after microtasks — a busy loop freezes the page.

Stack: main → foo → barOne function at a time, run to completion. The queue cannot interrupt. Web Workers are other stacks.

bar returns, stack emptyFrames pop. Nothing else runs until this stack is gone — including clicks, timers, and paint.

Queue: click, then setTimeout 0The loop picks one macrotask. Microtasks (plate 227) drain before the next task or render.

queue
What

Run-to-completion plus a queue. The queue cannot interrupt the stack. Microtasks sit in front of the next macrotask.

Why

“Why did my timeout fire late?” The stack was busy. Interviews: draw stack vs queue vs render.

Trap

“JS is multithreaded.” setTimeout(0) is not next-line — it is the next macrotask. A while(true) starves clicks, timers, and paint.
