FrontendCSR · SSR · SSG

Who builds the HTML?

Three answers. CSR: the server sends an empty shell, the browser builds the page. SSR: the server renders HTML per request, then the browser hydrates. SSG: HTML is built at deploy time. SEO, first paint, and personalization all hang on this choice.

Browser does it

CSR

<div id="root"></div> + bundle.js
Fast deploys. Great for dashboards.
First paint waits on JS.
Empty HTML for crawlers unless you cheat.

Server, each request

SSR

HTML with data then hydrate in the browser
User-specific HTML. Good SEO.
TTFB includes your DB.
Hydration must match the HTML.

At build time

SSG

npm run build → /docs/index.html
CDN-fast. Docs, blogs, marketing.
Stale until the next build.
Not for per-user data.
What

CSR = SPA. SSR = HTML on the server now (Next.js server components / getServerSideProps). SSG = HTML at build (or ISR: rebuild in the background). Hydration = attach events to existing HTML.

Why

Interviews ask this to see if you know why a blog and a logged-in app should not use the same strategy. Performance and SEO are consequences of who rendered.

Trap

SSR for a page that is all client state (you paid TTFB for empty useful HTML). SSG for prices that change every minute. Hydration mismatch: server HTML ≠ first client render (random ids, Date.now(), window).
