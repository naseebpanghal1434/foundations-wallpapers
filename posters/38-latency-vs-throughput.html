Systemp99 · L=λW

Latency is not throughput.

Latency is time for one request (ms). Throughput is completed work per second (req/s). Little’s law: in-flight L ≈ λ × W. A huge queue can raise throughput and wreck p99. Mean latency lies; p99 is what angry users hit.

one request

p50 80 ms

Median. Fine in a dashboard. Does not pay the incident.

the tail

p99 1.4 s

1 in 100 requests. GC, lock, cold cache, slow disk. This is the page that “hangs.”

capacity

1200 /s

Throughput. Add boxes if no shared bottleneck. Batch jobs want this; checkout may not.

Little

L = λW

1000 req/s × 0.10 s = 100 in-flight. Queues raise λ for producers and raise W for each job.

What

Add machines → throughput up (if no shared lock/DB). Faster code / cache / closer region → latency down. SLO is usually a latency percentile + error rate, not RPS alone.

Why

Interviews: “the API is slow.” Slow for one user (latency) vs cannot keep up (saturation) are different fixes. Measure both, plus errors — the golden three.

Trap

Optimizing the mean. Reporting only RPS. Adding replicas when the DB is the latency. Batching to help throughput and adding 400 ms to checkout.
