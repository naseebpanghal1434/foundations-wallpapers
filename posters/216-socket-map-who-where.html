NetworkWS · sticky · pub-sub

A socket needs a map of who is where.

A WebSocket is one fd on one box. Directory: SET user:42 nodeC EX 30. Push via PUBLISH; only that box writes the frame. Sticky L4 (plate 35) keeps the TCP. Linux default pipe/socket buffer is 64 KiB — history is the log (plate 202), not the kernel pipe.

Sticky WS to the edgeThe TCP lives on one box. Without sticky, the handshake lands where the socket isn’t. Fallback: SSE / long-poll if WS is blocked.

Publish on the busWorker PUBLISH user:42 msg (Redis / NATS). Any node may originate. Rooms: pub/sub on room id; shard the hot ones.

4

Owning box writes the framenodeC holds the fd. Kernel pipe is 64 KiB; 1M × 64 KiB = 64 GiB if full. History is the log, not this buffer.

64 KiB
What

Connection directory + pub/sub + sticky L4. Do not store the socket in Postgres. Fan-out to a room is pub/sub on room id, not a loop of 10k writes on one node.

Why

Chat / live comments / multiplayer. The map is the design. Without it you broadcast to every node, or you cannot find the user.

Trap

One Node process with all sockets. No sticky. Polling the DB for “messages to push.” Trusting half-open TCP — heartbeat or die. Treating the 64 KiB pipe as the conversation.
