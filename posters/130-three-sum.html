DSASkip duplicates

Sort. Then two pointers for three.

3Sum: unique triples a+b+c=0. Sort first. Fix i, then two-pointers on i+1..n−1 for the pair that sums to −a[i]. Skip duplicate a[i] and duplicate lo/hi values so each triple is unique. O(n²) time, O(1) extra besides sort.

Fix i · lo/hi on the rest

Sort + 2P

[-1,0,1,2,-1,-4] sort [-4,-1,-1,0,1,2] i at first -1: [-1,-1,2] and [-1,0,1] skip the second -1 as a fix lo starts at i+1, never 0

On a hit: record, skip equal a[lo]/a[hi], then lo++ hi--. Wrong sum: move one side.

vs

Hashset of pairs per i

Messy unique

no sort, no skip: [-1,0,1] twice from each -1 as i lo = 0: a[i] pairs with the left same index, or a used twice set of tuples: extra hash, slower to write

It can work. The expected write is sort, two pointers, skip-dups — uniqueness is the skip, not a set.

What

k-sum generalizes: sort, recurse k−1, two-pointers at k=2. Skip dups at every level. 4Sum is this with one more loop, still O(n³). Unsorted 3Sum with a hash is possible; uniqueness and the write are worse.

Why

LeetCode 15 / 16 / 18. The pattern is “reduce to 2Sum on a sorted array” (plates 54, 129). Say uniqueness is skip-dups, not an extra set of tuples.

Trap

Not sorting. Not skipping dups — floods the answer with repeats. Moving both lo and hi, or neither, when the sum is wrong. Starting lo at 0 so a[i] can pair with itself on the left.
