DSAHash · one pass

Remember what you already saw.

Two-sum: indices i < j with a[i]+a[j]=target. Nested loop is O(n²). Hash map: at i, if target−a[i] is in the map, return those indices; else map[a[i]]=i. One pass, average O(n). Sorted two-pointers is O(n) after sort but loses original indices unless you store them.

plate 54
What

Need indices → hash (plate 109). Need any pair on already-sorted data → two pointers. Need all unique pairs → sort + two pointers + skip dups (then 3Sum, plate 130). Average O(n) time, O(n) extra for the map.

Why

LeetCode 1 — the first problem and the hashmap pattern that repeats in the 3Sum family, two-sum in a BST, two-sum less than k. Say: “store the complement I already walked.”

Trap

Using the same index twice (look up after insert, or target=2*a[i] with one copy). Sorting in place when the caller wanted original indices. Two pointers on unsorted data — shrinking the range is a guess.
