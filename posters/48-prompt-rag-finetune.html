Gen AIin-context · retrieve · weights

Prompt, RAG, or fine-tune.

Three knobs. Prompt: instructions + few-shot in this request (minutes, window-limited). RAG: fetch top-k chunks at runtime (plate 12) so facts can change. Fine-tune: gradient updates to weights (SFT / LoRA) from hundreds+ labeled examples. Start left. Changing facts belong in the index, not the weights.

What

Prompt = in-context. RAG = retrieve then prompt. Fine-tune = gradient updates (LoRA is a small delta, plate 268). Tools (plate 47) are a fourth path: don’t memorize, call. You can combine all of them.

Why

The default wrong answer is “we’ll fine-tune on our PDFs.” That’s GPU hours and stale facts. Interviews want the ladder: prompt → RAG/tools → fine-tune only for behavior you cannot prompt.

Trap

Fine-tuning to “teach facts.” Fine-tuning on dirty data (it copies the dirt). RAG without eval. Pasting a 200-page policy into the window (plate 21) and calling it RAG.
