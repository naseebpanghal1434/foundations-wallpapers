LanguageBinding vs bytes · Object.is

const is not a freeze.

const locks the binding: user = {} is a TypeError; user.n = 2 is legal. Object.freeze(user) is shallow — nested objects still mutate. React (and memo) compare state with Object.is: same reference, no render. Immutability here means return a new object, not edit the old one.

Same pointer

In place

const user = { n: 1, addr: {} } user.n = 2 // allowed user = {} // TypeError items.push(x) setItems(items) // Object.is → skip Object.freeze(user) user.addr.city = "Y" // nested still writes

Freeze did not deep-seal addr. push returns a length, not a new array.

vs

New object, new identity

Replace

setItems([...items, x]) setUser({ ...user, n: 2 }) Object.freeze( structuredClone(user) )

Spread is shallow too — copy nested fields you plan to edit. Immer does the same job.

What

const/let are bindings (plate 68). Freeze is one-level. Deep freeze walks. React keys off reference equality (plate 67), not field diffs.

Why

A new ref is how the UI notices. A mutated cache entry is visible to every holder. Interviews: const vs freeze vs spread vs why the list didn’t rerender.

Trap

state.items.push then setState(state). setItems(items.push(x)) — push returns a number. Spreading once and mutating a nested object you still share.
