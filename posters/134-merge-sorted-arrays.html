DSATwo pointers · extra tail

Fill from the back.

Merge two sorted arrays. If nums1 has spare room at the end (length m+n), write from the back: the largest remaining goes to index m+n−1. Forward merge would overwrite unread nums1. If you own a new array, two pointers from the front are fine (merge lists, plate 146).

Tail is free · write largest

From the back

nums1=[1,4,7,_,_,_] m=3 nums2=[2,5,6] n=3 i=2 j=2 w=5 7 vs 6 → write 7 4 vs 6 → write 6 4 vs 5 → write 5 rest 1,2,4 → [1,2,4,5,6,7] leftover nums2 copies; leftover nums1 sits

w = m+n-1. Compare nums1[i] vs nums2[j], write the larger, decrement. O(m+n), O(1) extra.

trap

Write at 0 · unread tail dies

Clobber

start at 0, write 1,2,… clobbers 4 and 7 still needed later sorted descending? largest lives at 0 — then fill from the front new array / two lists: front merge is fine

The spare slots decide the write direction. Merge sort’s last step owns a new buffer, so it fills forward.

What

O(m+n) time, O(1) extra when the tail is free. Same pattern: merge from the side that has spare slots. Three indices: read nums1, read nums2, write.

Why

LeetCode 88. Also the last step of merge sort. Interviews watch whether you clobber unread values in nums1. Linked-list merge never clobbers — you own the links (plate 146).

Trap

Merging forward in nums1. Off-by-one on m+n-1. Copying nums1 leftovers unnecessarily (they are already in place). Sorted-descending arrays — then fill from the front.
