Frontendhistory.pushState · SSR

The URL is a state, not always a file.

An SPA changes the path with history.pushState and renders a component. The server still must answer that path on refresh — same HTML shell, or real SSR (plate 28).

Client-only path

Refresh 404

history.pushState({}, '', '/settings') // render <Settings /> // user hits refresh // nginx: 404

The server never heard of /settings. Hash routes (#/app) never hit the server.

trap

Server fallback

Same shell

location / { try_files $uri /index.html; } // or SSR the route

Back is popstate. replaceState for query tweaks you don’t want in history.

What

Client router + a server fallback. Deep links are a server problem. Search params are state you can share.

Why

The classic SPA refresh 404. Interviews: how routing works with a CDN.

Trap

Ignoring refresh. pushState in a loop. Putting secrets in the query string (logs, Referer).
