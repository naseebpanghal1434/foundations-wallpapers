DSAO(1) get and put

Hash finds. The list splices.

LRU cache: get and put in O(1), evict the least recently used when over capacity. Hash map key → node for O(1) find. Doubly-linked list with dummy head and dummy tail for O(1) splice (plate 104). Recency is the list order; the map is only an index.

cap=2 · dummyH and dummyT

Hash + DLL

put 1 H ⇄ 1 ⇄ T put 2 H ⇄ 1 ⇄ 2 ⇄ T get 1 move 1 to tail H ⇄ 2 ⇄ 1 ⇄ T put 3 unlink 2 (LRU) H ⇄ 1 ⇄ 3 ⇄ T map: 1→node, 3→node

Tail = most recent. H.next = victim. Map is key → node, not key → value alone.

vs

Cannot splice the middle

Queue + map

get(1) hits the map but the queue still has 1 sitting in the middle unlink = scan O(n) singly list: same scan for the victim

LFU needs a second structure (freq lists). OrderedDict is the language gift — still draw the DLL.

What

get: map lookup, move that node to the tail, return val or -1. put: update+move, or insert at tail; if over cap, unlink the least-recent (dummyH.next) and delete it from the map. Four pointer writes splice a node (plate 104).

Why

LeetCode 146. The design question. Say both structures in the first sentence. Dummy sentinels so you never null-check head or tail. O(1) get and put is the whole spec — a scan fails it.

Trap

Evicting the most recent. Forgetting to erase the victim from the map. Hash map of values with a queue you cannot splice. A singly-linked list that scans for the victim — that is O(n), not O(1).
