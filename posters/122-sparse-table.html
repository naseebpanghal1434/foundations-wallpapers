DSARMQ · idempotent

If it never updates, precompute.

A sparse table answers range min/max/gcd in O(1) after O(n log n) preprocess, if the array never changes. st[k][i] = f of 2^k elements starting at i. Overlap is OK because min (and gcd) do not care. Sum is not idempotent — overlapping would double-count, so sums stay prefix/Fenwick.

a = [2, 4, 1, 6, 3] · min

Two blocks

st[0] = a st[1][i] = min(a[i], a[i+1]) [2, 1, 1, 3] query [1,4) len=3 k = ⌊log2 3⌋ = 1 min(st[1][1], st[1][4-2]) = min(min(4,1), min(1,6)) = 1

k = 31-clz(len), or a precomputed log table. Second index is j − (1<<k).

vs

Overlap double-counts

Not sum

same two blocks: [4, 1] and [1, 6] min → 1 (the 1 once) sum → 4+1 + 1+6 = 12 middle twice true sum of 4,1,6 = 11

Idempotent: min, max, gcd, AND, OR. Sum and XOR need disjoint pieces — prefix or Fenwick.

What

Idempotent range ops only: min, max, gcd, AND, OR. O(n log n) space and build, O(1) query. No updates. Two overlapping 2^k windows cover [L, R] because f(x,x)=x.

Why

Static RMQ. LCA in a tree after Euler tour. When the interviewer says “array is immutable, many min queries.” One preprocess, then every query is two table hits.

Trap

Using it for sum. Updating one cell and forgetting the table is stale. Off-by-one on the second block: for half-open [L,R) it is R - (1<<k), for inclusive [L,R] it is R - (1<<k) + 1.
