FrontendDelegation · target

One listener. Many children.

A thousand rows do not need a thousand click handlers. Listen on the parent; event.target.closest tells you which child was hit — new rows bubble for free.

one handler per row

N listeners

rows.forEach(tr => tr.addEventListener('click', onRow) ) // memory // rows added later are deaf

Each node holds a function. Insert a row, forget to bind, it never fires.

vs

one bubble listener

Delegate

table.addEventListener('click', e => { const tr = e.target.closest('tr') if (!table.contains(tr)) return // use tr.dataset.id })

closest walks up. Matches dynamically added nodes. React: onClick on the list, data-id on the item.

What

One bubble listener on an ancestor. Filter by selector. Cheap for big lists. Capture delegation exists but is rare.

Why

Tables, menus, infinite scroll. Also why React can attach one listener at the root.

Trap

e.target is a nested <span> inside the row — use closest, not ==. Child stopPropagation so the parent never sees it. Delegating mouseenter (does not bubble).
