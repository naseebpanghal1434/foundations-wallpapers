NetworkSNI · coalescing · HTTP/2

One connection can serve many hosts.

HTTP/2 coalescing: if two hostnames share an IP and the cert covers both (SAN or wildcard), the browser may reuse one TLS connection. SNI named the host at handshake; :authority on each stream picks the host after that.

Same IP · cert covers both

One socket

a.cdn.com b.cdn.com A 203.0.113.8 SAN *.cdn.com SNI then :authority → 1 TLS, many streams

Partition cookies by host still. Coalescing is a client optimization, not a server toggle by name.

vs

Different IP or cert

Two sockets

a.cdn.com 203.0.113.8 b.cdn.com 203.0.113.9 or SAN misses b HTTP/1 cannot multiplex names on one fd anyway

CDNs love coalescing. Origin isolation hates a surprise shared connection.

What

Connection reuse across names when IP and cert both allow it. HTTP/1 cannot multiplex those names on one fd.

Why

Sharding on a CDN can collapse back to one connection (often good). A wildcard cert has blast radius.

Trap

Assuming Host: is isolated because you terminated TLS per domain on one IP — the client may still coalesce. Cookie Domain too wide (plate 280).
