DSANeed vs have counts

Cover t. Then shrink. That's the window.

Minimum window substring: smallest slice of s that covers every char of t — with counts, not as a set. Expand r; bump have only when a needed char's window count first equals need[c]. When have == need_n, shrink l, record best, then break the cover and repeat. O(|s|+|t|).

s=ADOBECODEBANC · t=ABC

Cover, shrink

need A1 B1 C1 need_n=3 ADOBEC have=3 len 6 A required — cannot drop CODEBA have=3 len 6 BANC have=3 len 4 ← min window[c]+=1 if c in need and window[c]==need[c]: have+=1 # not >=

Each index enters and leaves once. Among valids, take smallest r-l+1 (leftmost on a tie).

trap

have is requirements met

Not letters

have ≠ raw match count t=AABC need A:2 B:1 C:1 window A=1 → have not +1 window A=2 → have +1 # if window_map == need_map # every step: slow, easy to miss # t-dups treated as a set

have is how many of the need keys are currently satisfied. Shrink past a required char → decrement have.

What

Two maps (or a deficit array) plus two ints. Window is valid iff every t-char is covered at its required count. Then minimize length. Find-all-anagrams is the same counter with a fixed width |p|.

Why

LeetCode 76. The hard variable window: “smallest slice that satisfies a counter.” Say have/need out loud before you touch l.

Trap

Comparing full maps every step. Shrinking past a required char without decrementing have. Treating t as a set when it has duplicates. Case folding when the spec is case-sensitive.
