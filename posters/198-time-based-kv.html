DSAset · get ≤ t

Binary search the timestamps.

Time-based key-value store: set(key, value, timestamp) (timestamps per key increase), get(key, t) returns the value with the largest timestamp ≤ t. Map key → list of (ts, val). get is binary search (upper bound) on that list. O(log n) get. If timestamps are not sorted, you cannot log n.

1

Append if ts is monotonicset foo, bar, 1 then set foo, bar2, 4. Hash map of sorted arrays. Don’t binary search across keys. Decreasing timestamps break append — then you need an ordered map, not a push.

get is floor, not exactget foo,1 → bar; get foo,3 → bar (3 is a hole); get foo,4 → bar2; get foo,0 → empty. They want the latest value whose time is still ≤ t.

bisect_right, then −1Upper bound: first index with ts > t, then take the previous pair. Same bones as floor in an ordered map (plate 125). Snapshot array is this per index (LC 1146).

O(log n)
What

Hash map of sorted arrays. set is append if timestamps are non-decreasing. get is binary search for floor — upper bound, then index−1. Don’t binary search across keys. One list per key, not one global timeline.

Why

LeetCode 981 / 1146. Design + binary search. Interview: they want floor, not exact match. State the invariant: “largest ts ≤ t, or none.” Linear scan of the history is the fail they are fishing for.

Trap

Linear scan of the whole history. TreeMap per get without knowing the API. get exact t only — misses the hole at t=3. set with decreasing timestamps — then you need an ordered map, not an append.
