Frontendmax-age · no-store · private

Cache-Control is permission to keep it.

The browser (and CDN) may reuse a response only as the headers allow. max-age is seconds; no-store means do not write it; no-cache means revalidate before use — not “never cache.”

hashed assets

max-age

Cache-Control: max-age=31536000, immutable

Fingerprinted JS/CSS. Keep a year. private = browser only, not the CDN.

do not write

no-store

Cache-Control: no-store

Bank HTML. Forbidden. Not “ask first.”

store, then ask

no-cache

Cache-Control: no-cache ETag: "abc"

You may hold it. Must revalidate (plate 245). Meta tags are not this header.

What

Freshness vs revalidation vs forbidden. HTML usually revalidates; content-hashed JS/CSS can live a year.

Why

“Users see old app” after deploy: HTML was cached, or the JS URL didn’t change. Service workers (plate 246) can override.

Trap

no-cache as if it were no-store. Caching /index.html for a week. Putting max-age on a JSON API that includes the current user.
