DSAContiguous vs pointer hops

Arrays index. Lists hop.

An array is one contiguous block: index i is address + i × size — O(1). A linked list is nodes plus pointers: the 7th item is seven hops — O(n). Pick the layout for the operation you actually do.

One block in memory

Array

[ 7 | 2 | 9 | 4 ] 0 1 2 3 a[2] → 9 O(1) insert at 0 O(n) shift push at end amortized O(1)

CPU cache loves sequential reads. Random access is the point.

vs

Nodes + next pointers

Linked list

(7)→(2)→(9)→(4) index 2: hop hop O(n) insert after *p O(1) relink insert by value find first, O(n)

Splice is cheap only if you already hold the node. Doubly-linked adds prev.

What

Array = contiguous, O(1) index, O(n) insert/delete in the middle (shift). List = pointer hops, no O(1) index. Reverse a list, detect a cycle: you wanted nodes. Scan / sort / binary search: you wanted a block.

Why

SDE-1 screens ask “why is vector faster than list on a scan?” Cache lines. The O() is the same O(n); the constants are not. Know both costs: index and splice.

Trap

“Use a linked list, insert is O(1)” without a node pointer. Finding the spot is already O(n) — same as shifting in an array. Also: lists for random access. Also: head = head.next without keeping the old node you still need.
