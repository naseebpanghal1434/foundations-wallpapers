DSAComplete tree · array

Parent is at (i-1)/2.

A binary heap is a complete tree stored in an array. Index i has parent (i-1)//2, kids 2i+1 and 2i+2. Sift up after push, sift down after pop. Min-heap: parent ≤ kids. You cannot find an arbitrary key in O(log n) — that is a BST.

0-based · no holes

Array is the tree

1 / \ 3 2 / \ / 7 4 5 [1, 3, 2, 7, 4, 5] 0 1 2 3 4 5 parent of i=4 (val 4): (4-1)//2 = 1 → 3

Kids of i: 2i+1, 2i+2. Complete = filled level by level, so the array has no holes.

vs

Append, then sift

Push 0

append 0 → i=6 parent (6-1)//2 = 2 (val 2) 0 < 2 swap parent (2-1)//2 = 0 (val 1) 0 < 1 swap [0, 3, 1, 7, 4, 5, 2]

Pop = swap [0] with last, pop, sift down with the smaller kid. Peek is just [0].

What

Push O(log n), pop min/max O(log n), peek O(1), build O(n) bottom-up (sift down from n//2-1). 0-based: parent (i-1)//2, kids 2i+1 and 2i+2. 1-based is parent i//2, kids 2i and 2i+1 — pick one and stay there.

Why

Priority queue (plate 115), top-k, Dijkstra, heap-sort. Interviews: “implement a heap” means this indexing plus sift, not a picture of a tree.

Trap

Mixing 0-based kids 2i+1 with 1-based parent i//2. Using a heap as a search tree — “is 6 in here?” is O(n). Assuming heapsort is stable (it is not). Python heapq is a min-heap; max-heap via negatives.
