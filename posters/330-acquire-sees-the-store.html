LangC11 · memory_order

Acquire sees the store. Relaxed does not.

Atomics without a mutex still need an order. relaxed: atomicity only. An acquire load sees all stores before the matching release store. seq_cst: a global order, slowest. x86 is TSO — many orders compile to the same MOV; ARM and RISC-V do not.

Atomicity only · ARM stale

Relaxed

data = 42; flag.store(1, relaxed); if (flag.load(relaxed)) use(data); // may be stale // on ARM / RISC-V x86 TSO often hides this

A data race on a non-atomic is UB in C++ (plate 327). Wrong order on an atomic is a silent stale read.

vs

Happens-before

Acq / rel

data = 42; flag.store(1, release); if (flag.load(acquire)) use(data); // sees 42 seq_cst: one total order, more fences

Java volatile ≈ acquire/release. Go happens-before via channel send. Not C volatile (plate 331).

What

Release publishes prior writes; acquire observes them. Relaxed is a single atomic location with no envelope. seq_cst is a process-wide total order.

Why

Lock-free flags, once-flags, message passing without a mutex. The flag is the handshake; the payload is ordinary writes before the release.

Trap

Copying an x86-only mental model to ARM (phones, Apple silicon, Graviton). Using C volatile as a mutex (plate 331).
