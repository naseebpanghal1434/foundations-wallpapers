Langtry · Result · errno

Exceptions unwind. Result is a value.

throw walks frames until catch, running destructors/finally. Cost is on the throw path (and it can block inlining). Result/Either is a tagged value you match; nothing unwinds. errno is a thread-local int after a C call. Pick one policy per layer.

Rare · control flow

throw

try { foo() } catch (e) { … } finally { … }

Unwinds the stack. Cheap if you don’t throw. A thrown 404 in a hot parser is a problem.

Expected · a value

Result

Rust Result<T,E> Go (val, err) match / if err

File-not-found is data. Catching to convert to Result is a boundary, not a style mix inside a function.

C · thread-local int

errno

n = read(fd, …); if (n < 0) errno // ENOENT…

Return −1, then read errno. Not a global across threads. Ignoring it is a bug.

What

Control-flow vs data. Exceptions for rare failure; Result for expected failure. Mixing them is a layer boundary, not an accident in the middle of a loop.

Why

API design. Why Go doesn’t have exceptions. Why a hot parser that throws on every bad token is a profile, not a policy.

Trap

Using exceptions for every missing map key. Swallowing catch (Exception e) {}. Ignoring errno after a −1. Checking errno after a success.
